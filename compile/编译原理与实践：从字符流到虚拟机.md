## 1. 绪论：计算的本质

### 1.1 第一性原理：程序 = 数据 + 结构 + 解析

任何计算机程序的执行，都可以归结为三个核心环节：

1.  **程序是结构化的数据**：源码是字符串，但编译器将其解析为树形结构（AST）或线性结构（字节码）。
2.  **执行是结构的遍历**：解释器遍历树（jlox）或执行线性指令流（clox）。
3.  **硬件是固定的状态机**：CPU 做 fetch-decode-execute 循环，虚拟机模拟这一过程。

### 1.2 图灵完备性：什么决定了语言的能力？

一个语言要图灵完备，必须具备三个要素（加上状态存储）：

1.  **顺序执行**：指令按序推进。
2.  **条件分支**：`if` 语句选择路径。
3.  **循环/递归**：`while` 或函数递归实现迭代。
4.  **状态存储**：变量赋值（`var a = 1;`）。

**核心推论**：只要有 `if`、`while` 和变量，语言就能表达任何可计算函数。

### 1.3 文法分层：从正则到上下文无关

| 文法类型 | 识别能力 | 典型应用 |
| :--- | :--- | :--- |
| **正则文法（3型）** | 无记忆，只能识别重复模式（`a*`） | 词法分析（扫描器） |
| **上下文无关文法（2型）** | 有栈记忆，能识别嵌套配对（`(()))`） | 语法分析（解析器） |
| **上下文有关文法（1型）** | 有上下文记忆，图灵完备 | 语义分析 |

**关键洞察**：Python 和 Haskell 的词法并非正则（因为有缩进和嵌套注释），需要手写扫描器而非正则表达式生成器。

## 2. 第一部分：词法分析（扫描器）

### 2.1 第一性原理

**公理一**：计算机只能逐字符线性读取源代码，无法“一眼扫过”。

**公理二**：编程语言由有意义的语义单元（Token）构成，编译器必须先识别这些单元。

**公理三**：同一字符在不同上下文中有不同含义（`-` 既是一元负号也是二元减号）。

### 2.2 核心推论链条

```
逐字符读取 + 需要识别语义单元
→ 扫描器必须有循环遍历每个字符，在恰当边界切分 Token。

字符含义依赖上下文 + 需要判断当前字符属于哪种 Token
→ 扫描器必须能往前看（Lookahead）一两个字符。

需要往前看 + 不同 Token 规则不同
→ 扫描器按类型分支处理：单字符直接匹配，双字符试探，长 Token 用子程序。

分支处理 + 需要输出语义单元
→ 每识别完一个 Token，存入 Token 列表（类型、字面值、行号）。

需要处理无意义内容 + 需要错误恢复
→ 跳过空格/注释，遇到非法字符报告错误但继续扫描。
```

### 2.3 关键概念

| 概念 | 定义 | 代码示例 |
| :--- | :--- | :--- |
| **Token** | 最小语义单元 | `Token(TokenType.IDENTIFIER, "a", null, 1)` |
| **Lexeme** | Token 对应的原始字符子串 | `"123"` 在 `123` 中 |
| **关键字** | 保留的、有特殊语义的标识符 | `"if"`, `"while"`, `"var"` |
| **最长匹配** | 能匹配更长的 Lexeme 就优先匹配更长的 | `orchid` 不是 `or` |

### 2.4 jlox 扫描器实现

```java
class Scanner {
    private final String source;
    private final List<Token> tokens = new ArrayList<>();
    private int start = 0, current = 0, line = 1;

    List<Token> scanTokens() {
        while (!isAtEnd()) {
            start = current;
            char c = advance();
            switch (c) {
                case '(': addToken(LEFT_PAREN); break;
                case ')': addToken(RIGHT_PAREN); break;
                case '!': addToken(match('=') ? BANG_EQUAL : BANG); break;
                case '/':
                    if (match('/')) { while (peek() != '\n' && !isAtEnd()) advance(); }
                    else addToken(SLASH);
                    break;
                case ' ':
                case '\r':
                case '\t': break;
                case '\n': line++; break;
                case '"': string(); break;
                default:
                    if (isDigit(c)) number();
                    else if (isAlpha(c)) identifier();
                    else Lox.error(line, "Unexpected character.");
            }
        }
        tokens.add(new Token(EOF, "", null, line));
        return tokens;
    }
}
```

### 2.5 clox 按需扫描（On-Demand Scanning）

```c
typedef struct {
    TokenType type;
    const char* start;
    int length;
    int line;
} Token;

Token scanToken() {
    skipWhitespace();
    start = current;
    char c = advance();
    switch (c) {
        case '(': return makeToken(TOKEN_LEFT_PAREN);
        case ')': return makeToken(TOKEN_RIGHT_PAREN);
        case '!': return makeToken(match('=') ? TOKEN_BANG_EQUAL : TOKEN_BANG);
        case '/':
            if (match('/')) {
                while (peek() != '\n' && !isAtEnd()) advance();
                return makeToken(TOKEN_COMMENT);
            }
            return makeToken(TOKEN_SLASH);
        case '"': return string();
        default:
            if (isDigit(c)) return number();
            if (isAlpha(c)) return identifier();
            return errorToken("Unexpected character.");
    }
}
```

### 2.6 扫描器的职责边界

**扫描器做**：模式识别、Token切分、行号记录、基于字符类别的贪婪循环。

**扫描器不做**：语义理解、类型判断、数学变换、统计次数、后续解析凭证。

## 3. 第二部分：语法分析（解析器）

### 3.1 第一性原理

**公理一**：解析器是扫描器的逆过程——把平坦的Token序列重新组合成具有嵌套层次的树形结构。

**公理二**：上下文无关文法（CFG）本身不包含优先级和结合性信息。

**公理三**：递归下降解析器是文法规则的“逐字翻译”——每个产生式对应一个函数。

### 3.2 Lox 表达式文法

```text
expression  → literal
            | unary
            | binary
            | grouping ;

literal     → NUMBER | STRING | "true" | "false" | "nil" ;
grouping    → "(" expression ")" ;
unary       → ( "-" | "!" ) expression ;
binary      → expression operator expression ;
operator    → "==" | "!=" | "<" | "<=" | ">" | ">="
            | "+"  | "-"  | "*" | "/" ;
```

### 3.3 AST 节点定义

```java
abstract static class Expr {
    abstract <R> R accept(Visitor<R> visitor);
}

static class Binary extends Expr {
    final Expr left;
    final Token operator;
    final Expr right;
    Binary(Expr left, Token operator, Expr right) {
        this.left = left; this.operator = operator; this.right = right;
    }
    <R> R accept(Visitor<R> visitor) {
        return visitor.visitBinaryExpr(this);
    }
}

static class Literal extends Expr {
    final Object value;
    Literal(Object value) { this.value = value; }
    <R> R accept(Visitor<R> visitor) {
        return visitor.visitLiteralExpr(this);
    }
}
```

### 3.4 访问者模式（Visitor Pattern）

```java
interface Visitor<R> {
    R visitBinaryExpr(Expr.Binary expr);
    R visitLiteralExpr(Expr.Literal expr);
    R visitUnaryExpr(Expr.Unary expr);
    R visitGroupingExpr(Expr.Grouping expr);
}
```

**表达式问题（Expression Problem）**：访问者模式擅长扩展操作（新增Visitor），不擅长扩展数据类型（新增节点需修改所有Visitor）。

### 3.5 Pratt 解析器（优先级攀升）

```java
class Parser {
    private Expr parseExpression(int minPrecedence) {
        Expr left = parsePrefix();
        while (true) {
            Token op = peek();
            int precedence = getPrecedence(op.type);
            if (precedence < minPrecedence) break;
            consume(op);
            Expr right = parseExpression(precedence + 1); // 左结合
            // 右结合：parseExpression(precedence) 不加 1
            left = new Expr.Binary(left, op, right);
        }
        return left;
    }
}
```

**关键机制**：
- 左结合：`parseExpression(precedence + 1)` — 同优先级运算符不被右操作数吞掉。
- 右结合：`parseExpression(precedence)` — 同优先级运算符被右操作数递归处理。

### 3.6 表达式 vs 语句

| 维度 | 表达式（Expression） | 语句（Statement） |
| :--- | :--- | :--- |
| 核心使命 | 求值（产生值） | 执行（产生副作用） |
| 能否嵌套 | 可以无限嵌套 | 不能作为值嵌套在表达式里 |
| 是否必须产生值 | 是 | 否（void） |

## 4. 第三部分：语义分析（变量解析）

### 4.1 第一性原理

**公理一**：词法作用域是程序的静态属性——仅凭阅读源代码就能确定变量指向哪个声明。

**公理二**：变量引用遵循“最近匹配”原则——指向前文中最近的同名声明。

**公理三**：静态分析在执行之前对代码“预读”——只分析结构，不产生副作用，不受控制流影响。

### 4.2 Resolver 的职责

```java
class Resolver implements Expr.Visitor<Void>, Stmt.Visitor<Void> {
    private final Interpreter interpreter;
    private final Stack<Map<String, Boolean>> scopes = new Stack<>();
    private FunctionType currentFunction = FunctionType.NONE;
    private ClassType currentClass = ClassType.NONE;

    void resolve(List<Stmt> statements) {
        for (Stmt stmt : statements) {
            resolve(stmt);
        }
    }

    @Override
    public Void visitBlockStmt(Stmt.Block stmt) {
        beginScope();
        resolve(stmt.statements);
        endScope();
        return null;
    }

    @Override
    public Void visitVarStmt(Stmt.Var stmt) {
        declare(stmt.name);
        if (stmt.initializer != null) resolve(stmt.initializer);
        define(stmt.name);
        return null;
    }

    @Override
    public Void visitVariableExpr(Expr.Variable expr) {
        if (!scopes.isEmpty()) {
            Map<String, Boolean> scope = scopes.peek();
            if (scope.containsKey(expr.name.lexeme) && !scope.get(expr.name.lexeme)) {
                Lox.error(expr.name, "Cannot read local variable in its own initializer.");
            }
        }
        resolveLocal(expr, expr.name);
        return null;
    }
}
```

### 4.3 距离计算（静态偏移量）

```java
private void resolveLocal(Expr expr, Token name) {
    for (int i = scopes.size() - 1; i >= 0; i--) {
        if (scopes.get(i).containsKey(name.lexeme)) {
            interpreter.locals.put(expr, scopes.size() - 1 - i);
            return;
        }
    }
}
```

**距离（Distance）**：变量所在环境到当前环境需要跨越的 `enclosing` 层数，是一个编译期常量。运行时通过 `environment.getAt(distance, name)` 一步到位访问。

## 5. 第四部分：树遍历解释器（jlox）

### 5.1 第一性原理

**公理一**：解释器执行的是树形结构（AST），而非线性代码。

**公理二**：每个AST节点知道“怎么计算自己”，但计算逻辑与节点本身分离（访问者模式）。

**公理三**：Lox是动态类型语言——运算符行为取决于操作数的运行时类型。

### 5.2 Interpreter 核心实现

```java
class Interpreter implements Expr.Visitor<Object>, Stmt.Visitor<Void> {
    private Environment environment = new Environment();
    private final Map<Expr, Integer> locals = new HashMap<>();

    private Object evaluate(Expr expr) {
        return expr.accept(this);
    }

    @Override
    public Object visitBinaryExpr(Expr.Binary expr) {
        Object left = evaluate(expr.left);
        Object right = evaluate(expr.right);
        switch (expr.operator.type) {
            case PLUS:
                if (left instanceof Double && right instanceof Double)
                    return (Double)left + (Double)right;
                if (left instanceof String && right instanceof String)
                    return (String)left + (String)right;
                throw new RuntimeError(expr.operator, "Operands must be two numbers or strings.");
            case MINUS:
                checkNumberOperands(expr.operator, left, right);
                return (Double)left - (Double)right;
            case STAR:
                checkNumberOperands(expr.operator, left, right);
                return (Double)left * (Double)right;
            case SLASH:
                checkNumberOperands(expr.operator, left, right);
                return (Double)left / (Double)right;
        }
        return null;
    }

    @Override
    public Object visitLogicalExpr(Expr.Logical expr) {
        Object left = evaluate(expr.left);
        if (expr.operator.type == TokenType.OR) {
            if (isTruthy(left)) return left;  // 短路
        } else {
            if (!isTruthy(left)) return left; // 短路
        }
        return evaluate(expr.right);
    }
}
```

### 5.3 环境（Environment）链

```java
class Environment {
    private final Map<String, Object> values = new HashMap<>();
    final Environment enclosing;

    Environment() { enclosing = null; }
    Environment(Environment enclosing) { this.enclosing = enclosing; }

    void define(String name, Object value) {
        values.put(name, value);
    }

    Object get(Token name) {
        if (values.containsKey(name.lexeme)) return values.get(name.lexeme);
        if (enclosing != null) return enclosing.get(name);
        throw new RuntimeError(name, "Undefined variable '" + name.lexeme + "'.");
    }

    void assign(Token name, Object value) {
        if (values.containsKey(name.lexeme)) {
            values.put(name.lexeme, value);
            return;
        }
        if (enclosing != null) {
            enclosing.assign(name, value);
            return;
        }
        throw new RuntimeError(name, "Undefined variable '" + name.lexeme + "'.");
    }
}
```

### 5.4 控制流实现

```java
@Override
public Void visitIfStmt(Stmt.If stmt) {

        execute(stmt.thenBranch);
    } else if (stmt.elseBranch != null) {

    }
    return null;
}
```

### 5.5 函数与闭包

```java
class LoxFunction implements LoxCallable {
    private final Stmt.Function declaration;
    private final Environment closure;
    private final boolean isInitializer;

    @Override
    public Object call(Interpreter interpreter, List<Object> arguments) {
        Environment environment = new Environment(closure);
        for (int i = 0; i < declaration.params.size(); i++) {
            environment.define(declaration.params.get(i).lexeme, arguments.get(i));
        }
        try {
            interpreter.executeBlock(declaration.body, environment);
        } catch (Return returnValue) {
            if (isInitializer) return closure.getAt(0, "this");
            return returnValue.value;
        }
        if (isInitializer) return closure.getAt(0, "this");
        return null;
    }
}
```

**Return 异常机制**：`return` 通过抛出异常实现非局部控制流转移。

## 6. 第五部分：字节码虚拟机（clox）

### 6.1 第一性原理

**公理一**：程序的执行本质是“指令序列”在“状态机”上的连续运转。

**公理二**：字节码是“扁平化”的AST——嵌套的树结构被展开为线性的指令序列。

**公理三**：字节码块（Chunk）是一个动态数组，在编译过程中不断增长。

### 6.2 Chunk 与指令编码

```c
typedef enum {
    OP_CONSTANT,
    OP_CONSTANT_LONG,
    OP_ADD, OP_SUBTRACT, OP_MULTIPLY, OP_DIVIDE,
    OP_NEGATE,
    OP_RETURN,
} OpCode;

typedef struct {
    uint8_t* code;
    int count;
    int capacity;
    ValueArray constants;
    int* lines;
} Chunk;

void writeChunk(Chunk* chunk, uint8_t byte, int line) {
    if (chunk->capacity < chunk->count + 1) {
        int oldCapacity = chunk->capacity;
        chunk->capacity = GROW_CAPACITY(oldCapacity);
        chunk->code = GROW_ARRAY(uint8_t, chunk->code, oldCapacity, chunk->capacity);
        chunk->lines = GROW_ARRAY(int, chunk->lines, oldCapacity, chunk->capacity);
    }
    chunk->code[chunk->count] = byte;
    chunk->lines[chunk->count] = line;
    chunk->count++;
}
```

### 6.3 虚拟机核心执行循环

```c
typedef struct {
    Chunk* chunk;
    uint8_t* ip;
    Value stack[STACK_MAX];
    Value* stackTop;
    CallFrame frames[MAX_FRAMES];
    int frameCount;
    Table globals;
    Table strings;
    ObjUpvalue* openUpvalues;
    size_t bytesAllocated;
    size_t nextGC;
    Obj* objects;
} VM;

static InterpretResult run() {
    for (;;) {
#ifdef DEBUG_TRACE_EXECUTION
        printf("          ");
        for (Value* slot = vm.stack; slot < vm.stackTop; slot++) {
            printf("[ ");
            printValue(*slot);
            printf(" ]");
        }
        printf("\n");
        disassembleInstruction(vm.chunk, (int)(vm.ip - vm.chunk->code));
#endif
        uint8_t instruction = READ_BYTE();
        switch (instruction) {
            case OP_CONSTANT: {
                Value constant = READ_CONSTANT();
                push(constant);
                break;
            }
            case OP_ADD: {
                Value b = pop();
                Value a = pop();
                if (IS_NUMBER(a) && IS_NUMBER(b)) {
                    push(NUMBER_VAL(AS_NUMBER(a) + AS_NUMBER(b)));
                } else if (IS_STRING(a) && IS_STRING(b)) {
                    push(OBJ_VAL(concatenate(a, b)));
                } else {
                    runtimeError("Operands must be numbers or strings.");
                    return INTERPRET_RUNTIME_ERROR;
                }
                break;
            }
            case OP_RETURN: {
                Value result = pop();
                vm.frameCount--;
                if (vm.frameCount == 0) {
                    pop();
                    return INTERPRET_OK;
                }
                vm.stackTop = vm.frames[vm.frameCount].slots;
                push(result);
                break;
            }
        }
    }
}
```

### 6.4 值系统与 NaN 装箱

**优化前（16字节）**：
```c
typedef struct {
    ValueType type;
    union {
        bool boolean;
        double number;
        Obj* obj;
    } as;
} Value;
```

**优化后（8字节）**：
```c
#ifdef NAN_BOXING
typedef uint64_t Value;

#define QNAN 0x7ff8000000000000ULL
#define SIGN_BIT 0x8000000000000000ULL

#define IS_NUMBER(v) (((v) & QNAN) != QNAN)
#define IS_BOOL(v)   (((v) | 1) == TRUE_VAL)
#define IS_NIL(v)    ((v) == NIL_VAL)
#define IS_OBJ(v)    (((v) & (QNAN | SIGN_BIT)) == (QNAN | SIGN_BIT))

#define NUMBER_VAL(n) ((Value)(n))
#define BOOL_VAL(b)   ((b) ? TRUE_VAL : FALSE_VAL)
#define NIL_VAL       ((Value)(QNAN | 1))
#define OBJ_VAL(o)    ((Value)(SIGN_BIT | QNAN | (uint64_t)(uintptr_t)(o)))

#define AS_NUMBER(v)  ((double)(v))
#define AS_BOOL(v)    ((v) == TRUE_VAL)
#define AS_OBJ(v)     ((Obj*)(uintptr_t)((v) & ~(SIGN_BIT | QNAN)))
#endif
```

### 6.5 编译器：单遍编译直接生成字节码

```c
typedef struct {
    Token current;
    Token previous;
    bool hadError;
    bool panicMode;
} Parser;

typedef struct {
    ObjFunction* function;
    Local locals[UINT8_COUNT];
    int localCount;
    int scopeDepth;
} Compiler;

static void expression() {
    parsePrecedence(PREC_ASSIGNMENT);
}

static void parsePrecedence(Precedence precedence) {
    advance();
    ParseFn prefixRule = getRule(parser.previous.type)->prefix;
    if (prefixRule == NULL) {
        error("Expect expression.");
        return;
    }
    prefixRule();

    while (precedence <= getRule(parser.current.type)->precedence) {
        advance();
        ParseFn infixRule = getRule(parser.previous.type)->infix;
        infixRule();
    }
}
```

### 6.6 函数调用与栈帧

```c
typedef struct {
    ObjFunction* function;
    uint8_t* ip;
    Value* slots;
} CallFrame;

static bool call(ObjFunction* function, int argCount) {
    if (argCount != function->arity) {
        runtimeError("Expected %d arguments but got %d.", function->arity, argCount);
        return false;
    }
    if (vm.frameCount == MAX_FRAMES) {
        runtimeError("Stack overflow.");
        return false;
    }
    CallFrame* frame = &vm.frames[vm.frameCount++];
    frame->function = function;
    frame->ip = function->chunk.code;
    frame->slots = vm.stackTop - argCount - 1;
    return true;
}
```

### 6.7 闭包与 Upvalue

```c
typedef struct ObjUpvalue {
    Obj obj;
    Value* location;
    Value closed;
    struct ObjUpvalue* next;
} ObjUpvalue;

static ObjUpvalue* captureUpvalue(Value* local) {
    ObjUpvalue* prevUpvalue = NULL;
    ObjUpvalue* upvalue = vm.openUpvalues;
    while (upvalue != NULL && upvalue->location > local) {
        prevUpvalue = upvalue;
        upvalue = upvalue->next;
    }
    if (upvalue != NULL && upvalue->location == local) {
        return upvalue;
    }
    ObjUpvalue* createdUpvalue = newUpvalue(local);
    createdUpvalue->next = upvalue;
    if (prevUpvalue == NULL) {
        vm.openUpvalues = createdUpvalue;
    } else {
        prevUpvalue->next = createdUpvalue;
    }
    return createdUpvalue;
}

static void closeUpvalues(Value* last) {
    while (vm.openUpvalues != NULL && vm.openUpvalues->location >= last) {
        ObjUpvalue* upvalue = vm.openUpvalues;
        upvalue->closed = *upvalue->location;
        upvalue->location = &upvalue->closed;
        vm.openUpvalues = upvalue->next;
    }
}
```

## 7. 第六部分：内存管理（垃圾回收）

### 7.1 第一性原理

**公理一**：内存是有限的——程序持续分配堆对象，终将耗尽可用内存。

**公理二**：一个对象是否“需要”等价于它是否“可达”——是否存在某种方式让用户程序引用到它。

**公理三**：可达性是归纳定义的——所有根（Roots）可达，从可达对象引用的对象也可达。

### 7.2 标记-清扫（Mark-Sweep）

```c
typedef struct Obj {
    ObjType type;
    bool isMarked;
    struct Obj* next;
} Obj;

void collectGarbage() {
    markRoots();
    sweep();
    vm.nextGC = vm.bytesAllocated * GC_HEAP_GROW_FACTOR;
}

static void markRoots() {
    for (Value* slot = vm.stack; slot < vm.stackTop; slot++) {
        markValue(*slot);
    }
    for (int i = 0; i < vm.frameCount; i++) {
        markObject((Obj*)vm.frames[i].function);
    }
    for (ObjUpvalue* upvalue = vm.openUpvalues; upvalue != NULL; upvalue = upvalue->next) {
        markObject((Obj*)upvalue);
    }
    markTable(&vm.globals);
    markTable(&vm.strings);
}

static void sweep() {
    Obj* previous = NULL;
    Obj* object = vm.objects;
    while (object != NULL) {
        if (object->isMarked) {
            object->isMarked = false;
            previous = object;
            object = object->next;
        } else {
            Obj* unreached = object;
            object = object->next;
            if (previous != NULL) {
                previous->next = object;
            } else {
                vm.objects = object;
            }
            freeObject(unreached);
        }
    }
}
```

### 7.3 根集（Root Set）

clox 的根集包含三组数据：
1. **值栈（`vm.stack`）**：所有局部变量和临时表达式值。
2. **全局哈希表（`vm.globals`）**：所有用户定义的全局变量。
3. **开放 Upvalue（`vm.openUpvalues`）**：指向尚未被闭包持有的栈槽位。

### 7.4 循环引用处理

标记-清扫（Mark-Sweep）天然处理循环引用。只要循环中的任何节点不被根集可达，整个循环会被整体回收。无需像引用计数那样依赖弱引用或破裂机制。

## 8. 第七部分：面向对象系统

### 8.1 第一性原理

**公理一**：类是“创建实例的工厂”——类本身是一等公民，可以被存储、传递、返回。

**公理二**：实例是“动态的数据袋”——字段在运行时动态添加，无需在类中预先声明。

**公理三**：方法是“绑定到类”的函数——同一个类的所有实例共享同一套方法。

### 8.2 类与实例

```c
typedef struct ObjClass {
    Obj obj;
    ObjString* name;
    Table methods;
} ObjClass;

typedef struct ObjInstance {
    Obj obj;
    ObjClass* klass;
    Table fields;
} ObjInstance;

ObjInstance* newInstance(ObjClass* klass) {
    ObjInstance* instance = ALLOCATE_OBJ(ObjInstance, OBJ_INSTANCE);
    instance->klass = klass;
    initTable(&instance->fields);
    return instance;
}

static Value getProperty(ObjInstance* instance, ObjString* name) {
    Value value;
    if (tableGet(&instance->fields, name, &value)) return value;
    ObjFunction* method = tableFind(&instance->klass->methods, name);
    if (method != NULL) return OBJ_VAL(newBoundMethod(instance, method));
    runtimeError("Undefined property '%s'.", name->chars);
    return NIL_VAL;
}
```

### 8.3 绑定方法（Bound Method）

```c
typedef struct ObjBoundMethod {
    Obj obj;
    ObjInstance* receiver;
    ObjClosure* method;
} ObjBoundMethod;

static ObjBoundMethod* newBoundMethod(ObjInstance* receiver, ObjClosure* method) {
    ObjBoundMethod* bound = ALLOCATE_OBJ(ObjBoundMethod, OBJ_BOUND_METHOD);
    bound->receiver = receiver;
    bound->method = method;
    return bound;
}
```

### 8.4 继承与 `super`

**复制下传（Copy-down Inheritance）**：子类声明时，将父类的整个方法表复制到子类中。

```c
static void inheritMethods(ObjClass* subclass, ObjClass* superclass) {
    Table* to = &subclass->methods;
    Table* from = &superclass->methods;
    for (int i = 0; i < from->capacity; i++) {
        Entry* entry = &from->entries[i];
        if (entry->key != NULL && entry->key != EMPTY_KEY && entry->key != TOMBSTONE) {
            tableSet(to, entry->key, entry->value);
        }
    }
}
```

**`super` 的实现**：`super` 被编译为隐式局部变量，指向父类 `ObjClass`。`OP_GET_SUPER` 从父类方法表查找方法，`receiver` 依然是当前子类实例。

```c
static void super_(bool canAssign) {
    consume(TOKEN_DOT, "Expect '.' after 'super'.");
    consume(TOKEN_IDENTIFIER, "Expect superclass method name.");
    uint8_t name = identifierConstant(&parser.previous);
    namedVariable(parser.previous, canAssign);
    emitBytes(OP_GET_SUPER, name);
}
```

### 8.5 初始化器（`init`）

`init` 是特殊方法，在 `LoxClass.call()` 中自动调用。`init` 方法体执行完后，VM 返回实例本身（而非 `init` 的返回值）。

**返回值劫持防御**：
```c
try {
    interpreter.call(initializer, argCount, vm.stackTop - argCount);
} catch (Return returnValue) {
    // 忽略 init 返回的任何值
}
return instance;
```

## 9. 第八部分：性能优化

### 9.1 第一性原理

**公理一**：硬件太复杂，无法靠“纯推理”优化代码。优化是实证科学。

**公理二**：动态类型语言的性能瓶颈往往集中在“查找”上——全局变量、属性、方法调用都是哈希表查找。

**公理三**：CPU 的底层细节（如 IEEE 754 浮点数标准）中隐藏着未被利用的“信息空间”。

### 9.2 取模变与（位运算替代除法）

```c
// 优化前：取模运算（除法，慢）
static Entry* findEntry(Entry* entries, int capacity, ObjString* key) {
    uint32_t index = key->hash % capacity;
    // ...
}

// 优化后：位与运算（快）
static Entry* findEntry(Entry* entries, int capacity, ObjString* key) {
    uint32_t index = key->hash & (capacity - 1);
    // ...
}
```

**前提**：容量总是 2 的幂。

### 9.3 NaN 装箱（NaN Boxing）

将 `Value` 从 16 字节压缩为 8 字节，利用 IEEE 754 双精度浮点数中 NaN 的冗余位模式。

**位模式布局**：

```
普通数字：指数位不全为 1，可直接作为 double 使用。

NaN 装箱：
  QNAN = 0x7ff8000000000000ULL
  指针值 = QNAN | (uint64_t)ptr
  布尔值 = QNAN | 0x1 (false) 或 QNAN | 0x2 (true)
  nil值 = QNAN | 0x3
```

**类型判断**：`IS_NUMBER(v)` 只需 `(v) < QNAN`；`IS_OBJ(v)` 只需 `(v) >= QNAN`。

### 9.4 优化方法论

1. **测量（Profile）**：使用性能剖析器找到瓶颈（`tableGet` 占 72% 执行时间）。
2. **假设（Hypothesis）**：提出可能的优化方案（取模变与、NaN 装箱）。
3. **实现（Implement）**：修改代码，保持功能不变。
4. **验证（Verify）**：重新运行基准测试，确认性能提升。

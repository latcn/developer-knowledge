## 第一卷：项目概述与架构原则


### 一、项目定位与技术选型

| 项目 | 说明 |
| :--- | :--- |
| **产品名称** | WriteTrainer（写作训练 AI 助手） |
| **运行形态** | Web 应用，支持单机离线运行（内置默认数据降级）与云端模式（API 驱动） |
| **核心框架** | Vue 3（组合式 API）+ TypeScript + Vite |
| **状态管理** | Pinia（模块化 Store，支持持久化插件） |
| **UI 组件库** | Element Plus（按需加载，定制主题） |
| **样式方案** | Tailwind CSS + SCSS 变量系统 |
| **本地存储** | LocalStorage（配置/偏好/轻量数据）+ IndexedDB（作品/大文件） |
| **网络请求** | Axios（HTTP）+ 原生 WebSocket（如需要流式评价） |
| **Markdown 编辑** | 第三方 Vue Markdown 编辑器组件 |
| **图表可视化** | ECharts（按需加载，仅雷达图等核心图表） |


### 二、架构分层与职责划分

| 层级 | 职责 | 关键模块 |
| :--- | :--- | :--- |
| **展示层** | 页面渲染、用户交互、路由切换 | Views（Home / Training / Progress / Portfolio / Knowledge） |
| **组件层** | 可复用的 UI 单元，按功能域组织 | Common / Training / Portfolio / Progress |
| **状态管理层** | 全局数据状态管理、跨组件通信、持久化 | Pinia Stores（config / user / training / portfolio / knowledge） |
| **数据服务层** | API 调用、数据缓存、离线降级 | API 模块 + 本地默认数据 |
| **本地持久层** | 浏览器本地数据读写 | LocalStorage 工具 + IndexedDB 封装 |
| **逻辑复用层** | 跨组件的业务逻辑封装 | Composables（useConfig / useRankChecker / useLevelCalculator / useQuestionHistory） |


### 三、核心设计原则

1. **配置驱动**：等级定义、段位规则、七要素、专项定义等全部从后端 API 获取，支持热更新。前端内置完整默认数据作为降级兜底。
2. **能力本位**：等级（Level）反映用户真实写作能力，由规则引擎评分驱动，不依赖作品数量。
3. **成就校验**：段位（Rank）是“能力 + 行为”的综合认证，晋升时需同时满足作品数量和各专项等级门槛。
4. **数据可追溯**：每次训练记录完整保留原文、评价、修改迭代、用户反思，支持按题目/等级/时间多维度检索。
5. **类型安全**：前后端使用 OpenAPI 规范共享类型定义，前端自动生成 TypeScript 接口。
6. **渐进增强**：基础功能在无网络时仍可工作（内置题库 + 本地规则引擎），网络可用时获取最新配置和云端评价。


## 第二卷：数据模型（前端关心部分）


### 四、核心实体定义

以下为前端需要消费的核心数据类型，不包含具体代码实现，仅描述字段语义与业务用途。

#### 4.1 等级配置（LevelConfig）

| 字段 | 类型 | 业务含义 |
| :--- | :--- | :--- |
| `id` | 枚举字符串 | 等级唯一标识：`Lv.0-1` / `Lv.2-3` / `Lv.4+` |
| `name` | 字符串 | 等级显示名称（如“初阶”“进阶”“高阶”） |
| `order` | 数字 | 等级排序（0 / 1 / 2） |
| `visibleElements` | 字符串数组 | 该等级下可见的七要素 ID 列表（控制自检清单显示项数） |
| `trainingSteps` | 字符串数组 | 该等级下可用的训练步骤 ID 列表（控制三步/四步/七步流程） |
| `maxWordCount` | 数字 | 该等级下的建议最大字数 |
| `skillThresholds` | 键值对对象 | 达到该等级所需的各专项最低分数（Key 为专项 ID，Value 为 0-100 分数线） |
| `description` | 字符串 | 等级描述文案 |

**前端使用场景**：用户进入训练页时，根据当前等级决定题目字数上限、可见步骤、自检清单显示项数；在进度页展示等级晋升进度条时，计算各专项距离下一等级还差多少分。

#### 4.2 段位配置（RankConfig）

| 字段 | 类型 | 业务含义 |
| :--- | :--- | :--- |
| `id` | 字符串 | 段位唯一标识 |
| `name` | 字符串 | 段位显示名称 |
| `icon` | 字符串 | 段位图标（Emoji 或图标名称） |
| `order` | 数字 | 段位排序（决定晋升路径） |
| `conditions.requiredWorks` | 数字 | 晋升所需完成的作品数量（段位练习计数） |
| `conditions.requiredSteps` | 字符串数组（可选） | 晋升所需完成的特定训练步骤 |
| `conditions.levelPrerequisites` | 条件对象数组 | **核心**：晋升所需满足的专项等级门槛。每个条件包含 `skillId`（专项 ID）、`minLevel`（最低等级）、`minScore`（可选，同等级下的最低分数） |
| `unlocks` | 字符串数组 | 解锁内容说明（展示用） |
| `avgTime` | 字符串 | 预计耗时（展示用） |
| `enabled` | 布尔值 | 是否启用 |

**前端使用场景**：在进度页展示当前段位和下一个目标段位时，逐项渲染晋升条件清单（数量条件 + 各专项等级条件），并用“达标/未达标”状态区分；全部达标时显示“晋升”按钮。

#### 4.3 专项定义（SkillDefinition）

| 字段 | 类型 | 业务含义 |
| :--- | :--- | :--- |
| `id` | 字符串 | 专项唯一标识（`logic` / `sensory` / `emotion` / `expression` / `creativity`） |
| `name` | 字符串 | 专项显示名称（“逻辑编织力”“感官编码力”“情绪传递力”“精准表达力”“创意生成力”） |
| `description` | 字符串 | 专项核心定义 |
| `levelGoals` | 键值对对象 | 各等级下的训练目标描述（Key 为等级 ID，Value 为目标文案） |
| `icon` | 字符串 | 专项图标 |
| `color` | 颜色值 | 专项主题色 |

**前端使用场景**：在训练页选择专项时渲染卡片；在进度页雷达图中展示各专项得分；在段位晋升条件中展示专项名称映射。

#### 4.4 用户专项进度（UserSkillProgress）

| 字段 | 类型 | 业务含义 |
| :--- | :--- | :--- |
| `userId` | 字符串 | 用户标识 |
| `skillId` | 字符串 | 专项 ID |
| `currentLevel` | 字符串 | 当前等级（`Lv.0-1` / `Lv.2-3` / `Lv.4+`） |
| `currentScore` | 数字（0-100） | 当前综合得分 |
| `history` | 历史快照数组 | 等级变化历史：每条记录包含日期、等级、得分、触发变化的训练记录 ID |
| `trainingRecordIds` | 字符串数组 | 该专项下所有关联的训练记录 ID |
| `updatedAt` | 时间戳 | 最后更新时间 |

**前端使用场景**：在进度页展示各专项的当前等级和得分；在等级进度条中计算距离下一等级的差距；在段位晋升校验中比对是否满足最低等级要求。

#### 4.5 题目（Question）

| 字段 | 类型 | 业务含义 |
| :--- | :--- | :--- |
| `id` | 字符串 | 题目唯一标识 |
| `skillId` | 字符串 | 关联专项 ID |
| `title` | 字符串 | 题目标题 |
| `scene` | 字符串（Markdown） | 灵魂场景（题目主体描述） |
| `levelConfigs` | 等级配置数组 | **跨等级复用**：每个等级下包含 `levelId`、`requirements`（该等级的训练要求）、`maxLength`（字数上限）、`knowledgeHints`（知识库提示 ID 列表）、`difficulty`（难度系数） |
| `tags` | 字符串数组 | 标签 |
| `isActive` | 布尔值 | 是否启用 |

**前端使用场景**：训练页根据当前等级从 `levelConfigs` 中提取对应的训练要求和字数上限；历史页按题目聚合时，展示同一题目在不同等级下的训练记录分组。

#### 4.6 训练记录（TrainingRecord）

| 字段 | 类型 | 业务含义 |
| :--- | :--- | :--- |
| `id` | 字符串 | 记录唯一标识 |
| `userId` | 字符串 | 用户标识 |
| `questionId` | 字符串（可空） | 关联题目 ID（专项训练必填，段位练习可为空） |
| `skillId` | 字符串 | 关联专项 ID |
| `sessionType` | 枚举 | `skill`（专项等级训练）或 `rank`（整体段位练习） |
| `levelAtTraining` | 字符串 | 训练时的用户等级（实现“同题多级”的关键快照） |
| `title` | 字符串（可选） | 作品标题（段位练习通常用户自定义，专项训练自动生成） |
| `originalContent` | 字符串（Markdown） | 原始提交内容 |
| `revisedContent` | 字符串（Markdown，可选） | 当前最新修改内容 |
| `wordCount` | 数字 | 字数 |
| `evaluation` | 评价对象 | 完整评价报告：包含 `score`（得分）、`passed`（是否通过）、`rulePass`（规则是否通过）、`suggestions`（建议数组）、`encouragement`（鼓励语）、`details`（专项检测详情或七要素自检结果） |
| `status` | 枚举 | `pending` / `evaluated` / `passed` / `failed` / `revising` / `completed` |
| `iterationIds` | 字符串数组 | 关联的修改迭代 ID 列表 |
| `userNote` | 字符串（可选） | 用户反思/点评 |
| `instructorNote` | 字符串（可选） | 教练点评（预留） |
| `submittedAt` | 时间戳 | 首次提交时间 |
| `updatedAt` | 时间戳 | 最后更新时间 |
| `sevenElementReport` | 对象（可选） | 段位练习时的七要素自检报告 |

**前端使用场景**：在训练记录详情页展示完整内容、评价、修改历史；在题目展开视图中按等级分组展示；在作品集中展示段位练习作品列表。

#### 4.7 训练迭代（TrainingIteration）

| 字段 | 类型 | 业务含义 |
| :--- | :--- | :--- |
| `id` | 字符串 | 迭代唯一标识 |
| `recordId` | 字符串 | 关联训练记录 ID |
| `content` | 字符串（Markdown） | 本次修改的内容 |
| `wordCount` | 数字 | 字数 |
| `evaluation` | 评价对象（可选） | 本次修改的评价结果（得分、是否通过、建议） |
| `iterationNumber` | 数字 | 修改次数编号（第 1 次、第 2 次...） |
| `userNote` | 字符串（可选） | 用户本次修改的反思/说明 |
| `instructorNote` | 字符串（可选） | 教练点评（预留） |
| `createdAt` | 时间戳 | 提交时间 |

**前端使用场景**：在训练记录详情中展开显示所有修改迭代，按时间倒序排列；每条迭代显示内容、得分、用户反思。

### 七、训练核心页（Training）功能规格

这是整个应用最核心的页面，承载完整的“写-评-改”闭环。

#### 7.1 进入训练的模式

| 进入方式 | 触发条件 | 初始化逻辑 |
| :--- | :--- | :--- |
| **选择专项训练** | 用户点击“专项训练”入口 | 弹出专项选择面板 → 选择专项 → 调用出题接口（随机抽取该专项下当前等级的题目） → 渲染题目 |
| **选择段位练习** | 用户点击“段位练习”入口 | 调用出题接口（随机抽取段位练习场景题） → 渲染题目（不绑定特定专项，评价时使用七要素综合检测） |
| **继续已有训练** | 用户点击历史记录中的“继续训练” | 加载该记录的 `questionId` 和 `levelAtTraining` → 恢复题目和用户上次的 `revisedContent` → 进入修改模式 |
| **基于历史迭代继续** | 用户在历史详情中点击“基于此继续修改” | 加载该记录的最新内容 → 进入修改模式 → 提交时生成新的迭代记录 |

#### 7.2 训练流程步骤

| 步骤 | 功能 | 交互细节 |
| :--- | :--- | :--- |
| **出题展示** | 展示题目内容（场景描述、训练要求） | 题目卡片顶部显示专项名称和当前等级；场景部分使用蓝边引用块突出显示；底部显示“查看观察提示”按钮（弹出知识库抽屉）和“查看范例”按钮 |
| **作答区** | Markdown 富文本编辑 | 提供工具栏（加粗/斜体/引用/代码/链接/图片/无序列表/有序列表/表格/预览/全屏）；底部实时显示字数统计和进度条（超限时变红）；支持保存草稿（存 LocalStorage） |
| **七要素自检** | 根据等级显示 3/5/7 项自检清单 | 每个要素包含：自检引导问题、评分选项（0-3 分：未达标/勉强/合格/优秀）、备注输入框；未完成全部自检时提交按钮禁用 |
| **提交评价** | 调用评价接口 | 提交时携带：用户内容、当前等级、七要素自检报告、风格意图标记（如有）；展示加载状态；收到评价后展示评价报告 |
| **评价报告展示** | 展示检测结果与建议 | 显示：规则是否通过、得分（大号橙色数字）、通过/未通过状态、分项检测结果（行为词数/情绪词数/通顺度等）、改进建议列表（逐条展示）、鼓励语；未通过时显示“修改再提交”按钮，通过时显示“完成训练”按钮 |
| **修改迭代** | 用户修改后重新提交 | 进入修改模式时，编辑器加载 `revisedContent` 或 `originalContent`；提交时生成新的 `TrainingIteration` 记录；新的评价结果与历史评价并列展示；用户可在每次迭代时填写“修改反思” |
| **完成训练** | 评价通过后结束流程 | 自动保存作品到作品集（段位练习）或更新专项等级（专项训练）；展示完成证书或等级变化通知 |


### 八、进度页（Progress）功能规格

#### 8.1 段位晋升面板

| 功能 | 数据来源 | 交互要求 |
| :--- | :--- | :--- |
| **当前段位展示** | UserStore.unlockedRanks | 显示当前已解锁的最高段位名称和图标 |
| **下一目标段位** | RankChecker 计算逻辑 | 按 `order` 顺序查找第一个未解锁的段位，作为目标 |
| **晋升条件清单** | RankConfig.conditions | 逐项渲染：数量条件（已完成/需求） + 各专项等级条件（当前等级/需求等级），每项标记“达标/未达标”状态 |
| **晋升引导** | 未达标项自动生成建议 | 当专项等级未达标时，显示“建议完成 XX 专项训练提升等级”；点击建议可跳转至该专项的训练 |
| **晋升操作** | 全部达标时启用 | 显示“晋升段位”按钮，点击后调用后端晋升接口；成功后刷新页面数据，展示晋升动画或通知 |

#### 8.2 等级进度区

| 功能 | 数据来源 | 交互要求 |
| :--- | :--- | :--- |
| **当前等级** | UserStore.currentLevel | 显示等级名称和描述 |
| **等级阶梯图** | LevelConfig 列表 | 水平进度条显示所有等级（Lv.0-1 / Lv.2-3 / Lv.4+），已达成等级显示绿色，当前等级显示蓝色，未达成显示灰色 |
| **下一级差距** | LevelCalculator 计算 | 显示下一等级名称，以及各专项距离下一等级门槛还差多少分（如“逻辑编织力：45/60”），配以进度条可视化 |

#### 8.3 专项雷达图与技能树

| 功能 | 数据来源 | 交互要求 |

| **当前等级计算** | 根据用户各专项得分和等级配置的 `skillThresholds`，计算当前应属等级 |
| **下一级差距** | 计算下一等级的名称，以及各专项距离下一等级门槛的分数差距 |
| **等级达成度** | 计算当前等级下各专项的达成百分比（当前分数/该等级门槛分数） |

### 二十二、useRankChecker —— 段位校验器

| 功能 | 说明 |
| :--- | :--- |
| **单段位校验** | 接收段位 ID，返回校验结果：包含所有条件（数量条件 + 各专项等级条件）的达标/未达标状态 |
| **下一目标计算** | 自动查找下一个未解锁的段位，返回其校验结果 |
| **晋升建议生成** | 当专项等级未达标时，自动生成引导文案（“建议完成「XX 专项」训练，当前 X/需 X”） |
| **等级比较工具** | 提供等级大小比较方法（`Lv.4+ > Lv.2-3 > Lv.0-1`） |

### 二十三、useQuestionHistory —— 题目历史聚合器

| 功能 | 说明 |
| :--- | :--- |
| **按题目分组** | 接收题目 ID，从训练记录中筛选出该题目的所有记录 |
| **按等级分组** | 将筛选出的记录按 `levelAtTraining` 字段分组（Lv.0-1 / Lv.2-3 / Lv.4+） |
| **分组排序** | 组内记录按时间倒序排列，组间按等级从低到高排列 |
| **统计信息** | 返回总训练次数、涉及等级数量、各等级下的通过率 |


## 第七卷：网络与数据流


### 二十四、API 调用策略

| 场景 | 策略 |
| :--- | :--- |
| **配置加载** | 应用启动时调用 `/config/all`，设 5 秒超时；失败时使用缓存或默认数据，不阻塞界面渲染 |
| **出题** | 调用 `/questions/random`，设 3 秒超时；失败时从本地题库池中随机选取（降级） |
| **提交评价** | 调用 `/evaluate`，设 15 秒超时；展示加载状态，失败时提示用户重试 |
| **训练记录列表** | 优先从本地 IndexedDB 读取，同时后台请求远程数据更新本地缓存 |
| **作品集操作** | 单机模式下完全使用 IndexedDB；云端模式下同步调用后端接口 |

### 二十五、数据降级优先级

| 数据类型 | 第一优先级 | 第二优先级 | 第三优先级 |
| :--- | :--- | :--- | :--- |
| 等级/段位/要素配置 | 后端 API | LocalStorage 缓存 | 内置默认数据 |
| 题库 | 后端 API | IndexedDB 缓存 | 内置默认题库 |
| 知识库 | 后端 API | IndexedDB 缓存 | 内置默认知识库 |
| 用户进度 | 后端 API | LocalStorage | 初始默认值 |
| 训练记录 | 后端 API | IndexedDB | 空数组 |
| 作品内容 | 后端 API | IndexedDB | 空 |

### 二十六、本地存储方案

| 数据类型 | 存储方式 | 容量考虑 |
| :--- | :--- | :--- |
| 用户配置/偏好/进度 | LocalStorage | 单条 < 5KB |
| 训练记录索引 | LocalStorage | 每条 < 1KB |
| 题目内容/知识库卡片 | LocalStorage（缓存） | 总量 < 1MB |
| 作品内容（含版本） | IndexedDB | 单篇可 > 1MB，总量无硬性限制 |
| 历史迭代内容 | IndexedDB | 随训练次数增长 |

### 二十九、错误边界

| 错误类型 | 处理方式 |
| :--- | :--- |
| 配置加载失败 | 使用内置默认数据，在控制台输出警告，不阻塞应用 |
| 出题失败 | 使用本地题库降级，在界面顶部显示“使用本地题库”小标签 |
| 评价提交失败 | 保留用户内容，提示“评价失败，请检查网络后重试”，提供重试按钮 |
| IndexedDB 读写失败 | 降级使用 LocalStorage（作品内容存 JSON 字符串），提示“存储空间不足” |
| 页面路由异常 | 捕获并重定向至首页，显示“页面加载失败，已返回首页” |

## 第十一卷：总结

| 维度 | 本规格覆盖内容 |
| :--- | :--- |
| **架构原则** | 配置驱动、能力本位、成就校验、数据可追溯、类型安全、渐进增强 |
| **数据模型** | 等级配置、段位配置（含等级校验条件）、专项定义、用户专项进度、题目（跨等级）、训练记录（含迭代）、作品集 |

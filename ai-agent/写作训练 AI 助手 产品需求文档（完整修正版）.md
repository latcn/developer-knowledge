## 第一卷：产品战略与定位


### 一、文档说明

本文档以“**从不会写到能写出合格作品**”为产品使命，明确产品边界：只做 AI 擅长且有价值的“技能训练”部分，不追求培养文学大师。


### 二、产品背景

现有 AI 写作工具普遍聚焦于**直接生成内容**，通过 AI 续写、润色等功能，导致用户丧失自主构思、逻辑推演和文风打磨能力。市场存在以下未满足需求：

- **教育刚需**：高校写作课、职业培训中，学员缺乏实时、个性化反馈。
- **能力断层**：初学者依赖 AI 填充内容，长期使用者细节描写能力退化。
- **认知转变**：越来越多写作者意识到“能写出 10 万字”≠“掌握写作能力”，对“能力训练”需求上升。

产品机会明确：开发以“训练写作能力”为核心目标的 AI 助手，填补能力培养空白。


### 三、产品定位

本产品是帮助用户**从不会写作到能写出合格作品**的 AI 训练助手。

| 对比维度 | 传统 AI 写作工具 | 本产品 |
| :--- | :--- | :--- |
| 核心目标 | 快速产出内容 | 让用户能写出合格作品 |
| AI 角色 | 代笔者/润色者 | 教练 + 陪练 |
| 用户参与度 | 低（一键生成） | 高（全程手动创作与修改） |
| 评价方式 | 结果导向 | 过程与能力导向 |
| 长期价值 | 内容资产 | 能力资产 + 个人成长数据 |
| 激励机制 | 字数/完成度 | 能力提升 + 技能树点亮 |


### 四、核心理念

1. **强制用户主导创作**：AI 严禁替代用户完成核心创作，仅扮演引导者、诊断者和反馈者。
2. **先完成，再完美**：通过极简闭环让 Lv.0-1 用户先“写出来”，再逐步引入更复杂的流程。
3. **训练而非代写**：产品的核心目标是提升用户能力而非产出内容。
4. **渐进式解锁**：训练流程按等级逐步解锁，避免认知过载。
5. **分类施教**：根据用户的创作题材倾向，动态调整训练模块的优先级和解锁节奏。


### 五、产品边界声明

**本产品“教什么”：**
- 如何管理灵感、塑造人物、构建世界
- 如何设计激励事件、放大矛盾、搭建结构
- 如何写出让读者看明白的场景、对话和情节
- 如何系统性地修改自己的作品

**本产品“不教什么”：**
- 如何成为文学大师
- 如何写出“直触人心”的惊天之作
- 如何进行深刻的哲学思辨和人性洞察


### 六、合格作品的标准：七要素

在开始训练之前，用户需要知道“合格作品”长什么样。产品中明确定义“合格作品”的七个维度。

| 要素         | 定义        | 合格标准（Lv.0-3）         | 进阶标准（Lv.4+）    |
| :--------- | :-------- | :------------------- | :------------- |
| **情节**     | 事件的发展与转折  | 有明确因果关系，读者能复述“发生了什么” | 紧凑有悬念，高潮有冲击力   |
| **结构**     | 起承转合的布局   | 有开端-发展-结尾的完整框架       | 节奏张弛有度，符合叙事弧线  |
| **人物**     | 立体有动机的角色  | 主角有明确目标和基本动机         | 次要角色立体，主角有成长弧光 |
| **场景**     | 细节生动的环境   | 读者能“看见”场景的基本画面       | 多感官融合，氛围与情绪呼应  |
| **对话**     | 推动情节或揭示性格 | 对话能传递信息、区分人物         | 对话自然、有潜台词、推动冲突 |
| **风格**     | 语言特色和叙事视角 | 语言通顺、无语病             | 有辨识度、叙事视角统一    |
| **意义（主题）** | 核心思想或隐喻   | 故事有基本意图              | 主题有深度，引发思考     |

**七要素渐进式引入**：

| 等级         | 关注的要素               | 原因                    |
| :--------- | :------------------ | :-------------------- |
| **Lv.0-1** | 情节 + 人物 + 场景        | 核心是“能写出来”，三个要素足够覆盖微故事 |
| **Lv.2-3** | 增加 结构 + 对话          | 短篇需要结构支撑，对话推动情节       |
| **Lv.4+**  | 完整引入全部七要素（含风格 + 主题） | 完整作品需要全面质量参照          |

### 九、用户自评工具

**核心原则**：不给用户“自评负担”，只采集“行为描述”——用户不需要判断好坏，只需要描述自己的习惯。

**阶段一：进入训练前的快速诊断（选择题，3 分钟）**

| 维度 | 选择题（描述行为，非价值判断） |
| :--- | :--- |
| 场景 | **你写场景时通常会：** A. 只写看到的东西 B. 写看到和听到的 C. 视听说触嗅都有涉及 |
| 结构 | **你写的故事中段通常：** A. 不知道写什么就停了 B. 有内容但感觉平 C. 能保持张力 |
| 人物 | **你的人物通常是：** A. 想到谁就写谁 B. 会提前想一下性格 C. 会写详细的人物卡 |
| 对话 | **你写对话时：** A. 想到什么写什么 B. 会区分说话方式 C. 会让每句话都有潜台词 |

**阶段二：完成 3 个微故事后，系统自动生成“能力诊断报告”**

- 不依赖用户自评，基于用户在实际训练中的表现数据
- 系统自动标注：场景中视觉占比、对话中角色区分度、人物欲望清晰度等
- 数据驱动，精准定位薄弱点


## 第三卷：核心训练流——渐进式七步法


### 十、设计理念

本产品将七步法设计为**三层漏斗结构**，不同等级用户看到不同长度：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    七步完整闭环（Lv.4+）                            │
│  ①捡种子（灵感+人物）→ ②砸石头（启动事件）→ ③加猛料（放大与延展）   │
│  → ④画图纸（结构大纲）→ ⑤盖房子（完成初稿）→ ⑥晾一晾（冷却与互评）  │
│  → ⑦搞装修（系统修改）                                             │
├─────────────────────────────────────────────────────────────────────┤
│                    四步标准版（Lv.2-3）                             │
│      ①捡种子 → ②砸石头 → ③加猛料 → ⑤盖房子                       │
├─────────────────────────────────────────────────────────────────────┤
│                    三步极简闭环（Lv.0-1）                           │
│            ①捡种子 → ②砸石头 → ⑤盖房子                            │
│                    → 产出 500 字微故事                              │
└─────────────────────────────────────────────────────────────────────┘
```

**新手友好命名（UI 主标题 + 副标题）** ：

| 步骤 | UI 主标题 | 副标题（专业术语） | 核心动作 |
| :--- | :--- | :--- | :--- |
| 第 1 步 | **捡种子** | 灵感 + 人物 | 记录观察 + 赋予欲望 |
| 第 2 步 | **砸石头** | 启动事件 | 打破平静 + 写出场景 |
| 第 3 步 | **加猛料** | 放大与延展 | 矛盾升级 + 场景延展 |
| 第 4 步 | **画图纸** | 结构大纲 | 结构模型 + 大纲规划 |
| 第 5 步 | **盖房子** | 完成初稿 | 连续写作 + 完整作品 |
| 第 6 步 | **晾一晾** | 冷却与互评 | 匿名评审 + 获得反馈 |
| 第 7 步 | **搞装修** | 系统修改 | 五层修改 + 打磨作品 |


### 十一、第一层：Lv.0-1 三步极简闭环

目标：**“我能写完一个故事”**

#### 第 1 步：捡种子（灵感 + 人物）

| 子任务 | 训练内容 | AI 角色 |
| :--- | :--- | :--- |
| 灵感卡片 | 填写 What/Why/How 三栏 | 引导者：提示观察方向 |
| 人物速写 | 100 字描写 + 一句欲望句 | 提问者：“他想要什么？” |

**题目示例**：
> 📝 **灵感卡片**
> What（我观察到的细节）：______
> Why（为什么吸引我）：______
> How（可以怎么用在故事里）：______

> 📝 **人物速写**
> 他叫______，他正在______，他真正想要的是______。

#### 第 1 步 → 第 2 步的过渡引导 `[修订：由文字段落升级为交互式填空]`

用户完成第①步后，系统自动触发以下过渡引导，帮助用户将“种子”转化为“石头”：

**[修订] 此模块在UI中以独立卡片形式呈现，包含三个必答填空题，而非纯文字说明：**

> 💡 **从“种子”到“石头”——关键一跃**
>
> 你记录的细节和创造的人物之间，缺一个**“砸进去”的时刻**。请逐一回答以下三个问题（每问限 50 字内）：
>
> | 引导问题 | 你的回答 |
> | :--- | :--- |
> | ① 这个种子指向了谁的生活？ | ______ |
> | ② 谁最不希望这件事发生？ | ______ |
> | ③ 如果这件事在他最没准备时降临，会怎样？ | ______ |
>
> 回答完毕后，系统将自动拼接你的三句回答，合成一段**“启动事件速写”**（AI 仅做拼接，不新增内容），作为第②步的起点。
>
> *💡 示例：你记录了“地铁上发呆的人”，你创造了“李明，35岁，刚被裁员”——如果下一秒他的手机响了，屏幕上是 HR，而妻子就站在三米外……这就是你的“石头”。*

#### 第 2 步：砸石头（启动事件）

| 子任务 | 训练内容 | AI 角色 |
| :--- | :--- | :--- |
| 激励事件设计 | 打破人物平静，制造不可逆改变 | 检验者：“还能回去吗？” |
| 场景五步法 | 起始点→状态→转折→冲突→结果 | 陪伴者：逐填空引导 |

**场景五步法填空**：
> 第一步（地点 + 人物）：______
> 第二步（主角想干什么）：______
> 第三步（什么打破了状态）：______
> 第四步（他如何应对）：______
> 第五步（结果 + 下一步）：______

#### 第 5 步：盖房子（完成初稿）

| 子任务 | 训练内容 | AI 角色 |
| :--- | :--- | :--- |
| 扩展写作 | 将场景扩展为 500 字完整故事 | 陪伴者：鼓励完成 |
| 完成证书 | 自动生成微故事完成证书 | 系统自动颁发 |

**关键机制**：
- AI **不做任何文学评判**，仅做三件事：填空是否填了、是否有语病、给予鼓励反馈
- 完成三步后，系统自动生成“微故事完成证书”

**幻想类用户特殊处理**：若用户选了“幻想/科幻”题材，在第①步后插入可选的**世界设定速写**（力量体系核心规则），作为启动事件的上下文。此步骤为“可选加速包”，不强制。


### 十二、第二层：Lv.2-3 四步标准版

完成 3 个微故事后自动解锁第③步。

#### 第 3 步：加猛料（放大与延展）

| 子任务 | 训练内容 | AI 角色 |
| :--- | :--- | :--- |
| 放大矛盾 | 三种方法选一种：连锁反应 / 压力递增 / 揭露真相 | 推演者：“更糟的情况是什么？” |
| 场景延展 | 将矛盾升级转化为具体场景 | 引导者：逐场景构建 |

**放大矛盾三种方法（三选一）** ：

| 方法 | 训练方式 | AI 辅助 |
| :--- | :--- | :--- |
| 连锁反应法 | 推演 3 层后果 | AI 画出因果链图 |
| 压力递增法 | 升级冲突 3 次 | AI 问“更糟的情况是什么？” |
| 揭露真相法 | 揭示深层真相 | AI 引导“还有什么可能？” |

#### 第 4 步：画图纸（结构大纲）

此阶段**只提供“故事圈”这一种结构模型**，不给选择。 `[修订：节点主标题替换为极简版，降低认知门槛]`

| 节点 | UI 主标题 `[修订]` | 专业术语（副标题） | 训练要求 | AI 检验 |
| :--- | :--- | :--- | :--- | :--- |
| 原点 | **他缺什么？** | 缺失与渴望 | 主角缺少什么？ | 是否明确回答了？ |
| 上升 | **他得到了，但还不够** | 获得与贪婪 | 得到了但想要更多？ | 是否有“得到还不够”的节奏？ |
| 顶点 | **最糟的时刻到了** | 代价与转折 | 欲望膨胀到极致后？ | 是否有“无可回头点”？ |
| 回归 | **他变了吗？** | 失去与原点 | 回到原点——但人不同了 | 是否体现了变化？ |

**故事圈填空**：
> 原点（他缺什么？）：______
> 上升（他得到了什么？还想要什么？）：______
> 顶点（最糟的时刻——他失去了什么无法承受的东西？）：______
> 回归（他变了吗？）：______

`[修订] 新增提示`：*💡 新手最容易在“最糟的时刻”写得太轻——请确保主角在这个节点失去了某样他无法承受失去的东西。*

**Lv.2-3 AI 评价边界**：
- ✅ 检测：四节点是否填了、转折点是否写了、场景四要素是否齐全
- ❌ 不做：“转折是否有冲击力”“人物是否立体”


### 十三、第三层：Lv.4+ 七步完整闭环

完成 2 个四步短篇后自动解锁第⑥⑦步。

| 步骤 | 训练内容 | 新增工具 |
| :--- | :--- | :--- |
| ①-⑤ | 同四步标准版 | 同左 |
| **⑥晾一晾** | 冷却期 + 匿名读者反馈 | 读者感受词云 + 读者积分 |
| **⑦搞装修** | 五层修改法 | 结构→场景→语言→冷读→通读 |

#### 第 6 步：晾一晾（冷却与匿名读者反馈）

**冷却期流程（修正版）** ：

```
完成初稿 → 进入“晾晒场” → 24 小时倒计时开始
                              ↓
            ⏰ 立即触发“第一印象快速反馈”
            AI 模拟 3 位读者阅读前 200 字后的即时反应
            （3 个情绪标签 + 一个词评价）
            → 让用户在冷却开始前就获得一次激励
                              ↓
            ⏰ 2 小时内触发第一次互评推送：
            “现在，你来当一回读者——读一篇匿名初稿，选出你的感受词”
                              ↓
            用户完成 1 次匿名评审 → 获得“读者积分”+ 查看自己的实时反馈
                              ↓
            [新增] ⏰ 系统检测：若提交后 6 小时内未获得 ≥2 位真人读者反馈
            → 自动触发 AI 模拟读者反馈（兜底方案）
            → 输出 3 个感受词 + 一句话评语，视觉上以灰色边框 + 🤖 标识区分
            → 用户可标记“这个 AI 反馈有用/无用”，用于优化兜底算法
                              ↓
            每 4-6 小时推送一次新任务（共 3-4 次）
                              ↓
            24 小时后 → 收到完整的“感受词云”汇总报告
```

**第一印象快速反馈** `[修订：新增“困惑”标签解读]`：

用户提交初稿后，系统立即生成初稿的“第一印象快速反馈”——AI 模拟 3 位读者阅读前 200 字后的即时反应，输出形式为“3 个情绪标签 + 一个词评价”。

示例：
> 📊 **第一印象快速反馈**
> 你的开头给读者的第一印象是：
> 🏷️ **好奇** | **紧张** | **困惑**
> 📝 “这个开头让我想继续读下去，因为……”
>
> *注：这是 AI 模拟 3 位读者读完前 200 字后的即时反应，仅供参考。*
>
> `[修订]` **标签解读**：
> - **“好奇”** → 读者产生了疑问，愿意继续看下去（积极信号）
> - **“紧张”** → 读者感受到了压力或冲突（积极信号）
> - **“困惑”** → 读者没看懂发生了什么（⚠️ 可能是悬念设置成功，也可能是信息交代不足，请自行判断——如果前 200 字确实埋了伏笔，困惑就是好事；如果只是没写清楚，建议补充必要信息）

**匿名读者感受词云**：

- 用户冷却期间，系统将用户的初稿（匿名化）推送给其他处于冷却期的用户
- 被推送的用户只需做一件事：在 5 个感受词中选 3 个
- 词库：紧张 / 困惑 / 感动 / 愤怒 / 好奇 / 无聊 / 兴奋 / 悲伤 / 期待 / 压抑
- 冷却期结束后，用户收到 3-5 位匿名读者的“感受词云”

**读者积分机制**：

| 动作 | 积分 | 积分用途 |
| :--- | :--- | :--- |
| 完成 1 次匿名评审 | +10 分 | 兑换额外评价次数 |
| 评审质量被评价为“有帮助” | +5 分 | 兑换专属分析报告 |
| 累计评审 10 次 | +50 分（里程碑） | 解锁高级参照库 |

积分排行榜仅向用户展示个人累计值（“你已帮助 12 位作者获得反馈”），不公开排名。

### 十五、破格训练——打破模型

#### 15.1 设计背景

网文爽点波浪模型和故事圈结构提供了清晰的创作框架，但过度依赖框架会导致作品同质化。真正的独立作者，不仅要知道“如何遵循规则”，更要懂得“何时打破规则”。

#### 15.2 解锁条件

用户完成 3 个“模型内作品”后，自动解锁“破格训练”入口。

#### 15.3 核心机制

| 规则 | 说明 |
| :--- | :--- |
| **3+1 破格比例** | 每完成 3 个使用标准模型的作品，必须完成 1 个“破格作品”才能晋升下一段位 |
| **破格任务生成** | 系统根据用户最近使用的模型，自动生成 3 个破格挑战，用户三选一 |
| **破格不降级** | 破格作品的 AI 评价将**自动降级为 Lv.2-3 模式**（仅检测规则遵守，不做文学判断），避免用户在挑战规则时被“不符合标准”的评价打击 |

#### 15.4 破格挑战库

| 模型 | 破格挑战 |
| :--- | :--- |
| 故事圈 | 刻意省略“回归”节点——故事在主角失去一切后结束，不给任何归乡 |
| 故事圈 | 反转“原点→上升→顶点→回归”的顺序——从顶点开始写，再用倒叙揭示“他是怎么走到这一步的” |
| 网文波浪模型 | 第 10-15 章不安排任何爽点——让主角持续受挫，验证读者是否会因“期待延迟”而追读 |
| 网文波浪模型 | 黄金三章内不给金手指——让读者先认同主角的“人”，再展示他的“能” |
| 英雄之旅 | 省略“拒斥召唤”环节——主角毫不犹豫地接受冒险，看故事如何变异 |

#### 15.5 破格作品标注

所有破格作品在用户作品集中以特殊徽章（💥）标记，作为“敢于打破常规”的能力证明。

## 第五卷：卡文急救包


### 二十二、功能定位

网文作者和连载作者最高频的痛点是**日更卡文**。本功能帮助打破思维僵局，而非替代创作。

### 二十三、功能设计

| 触发方式 | 输出 |
| :--- | :--- |
| 用户主动点击“卡文急救” | 3-5 个推演分支供选择 |
| 系统检测停留超过 10 分钟无输入 | 1 个温和的“What if”提示 |

### 二十四、急救策略库

| 策略 | 示例 | 适用场景 |
| :--- | :--- | :--- |
| **“What if”推演** | “如果突然闯入一个不速之客？” | 情节推进卡住 |
| **“最坏选择”** | “如果主角做了最糟糕的选择？” | 需要制造冲突转折 |
| **“视角切换”** | “从另一个角色视角描述这一幕？” | 叙述节奏单一 |
| **“环境介入”** | “如果此刻突然停电/暴雨？” | 场景张力不足 |
| **“素材库推荐”** | 从用户灵感卡片库推荐 1 张相关卡片 | 需要注入新元素 |

### 二十五、核心原则

- **AI 不提供续写文本**：只提供推演方向（50 字以内的问题式提示）
- **用户必须自己写出结果**：保持“强制用户主导创作”原则
- **急救记录**：每次使用后记录策略类型和效果，优化推荐算法


## 第六卷：知识库设计


### 二十六、知识库概述

知识库是贯穿训练全流程的“智能教学引擎”，而非静态词汇表。

**核心原则**：
- **观察提示卡 > 标准答案**：不提供“写悲伤就用 A、B、C 词”，而是提供“观察人在悲伤时，呼吸和肩膀会有什么变化？”
- **初级锦囊（默认折叠）** ：对零基础用户提供“常见选择”作为脚手架
- **经典参照 > 随意举例**：所有范例优先从经典作品中提取

### 二十七、知识库分类

| 知识库分类 | 对应训练 | 内容形式 | 初级锦囊（折叠） |
| :--- | :--- | :--- | :--- |
| 灵感素材库 | 创意生成力 | 经典拆解、置换范例 | 10 个经典“如果”变体 |
| 人物档案库 | 创意生成力 | 人物原型、弧光案例 | 20 组“特质→极端情境” |
| 世界设定库 | 逻辑编织力 | 历史锚定、架空范例 | 10 个世界设定快速模板 |
| 结构模型库 | 逻辑编织力 | 故事圈/英雄之旅/金字塔模板 | 三模型填空模板 |
| 感官观察卡 | 感官编码力 | 五感观察提示（启发式） | 常见感官表达参考表 |
| 情绪观察卡 | 情绪传递力 | 情绪→身体反应提示 | 常见情绪表达参考表 |
| 修改工具箱 | 精准表达力 | 五层修改检查清单 | 对话辨识度自测表 |

### 二十八、观察提示卡示例 `[修订：初级锦囊升级为“选项+追问”]`

| 传统词典方式（易僵化） | 观察提示卡（启发观察） | `[修订]` **初级锦囊（折叠 · 选项+追问）** |
| :--- | :--- | :--- |
| 紧张→吞咽、目光漂移、手抖 | 紧张时喉部变化？手部不自觉动作？目光看向哪里？ | **选一个**：A. 喉结上下滑动 B. 手指反复摩挲 C. 目光快速扫视<br>**+ 追问**：选完后问自己——这个动作发生时，他在掩饰什么？ |
| 悲伤→喉咙发紧、眼眶发热 | 强忍悲伤时，面部肌肉、呼吸节奏、声音的变化？ | **选一个**：A. 嘴角微微抽搐 B. 深吸一口气缓缓吐出 C. 声音比平时低一个调<br>**+ 追问**：选完后问自己——他忍住的悲伤，会在哪个瞬间彻底崩掉？ |
| 愤怒→脸红、攥拳、咬牙 | 压制愤怒时，身体哪些部位会出卖他？ | **选一个**：A. 下颌线紧绷 B. 指关节发白 C. 说话变慢、咬字加重<br>**+ 追问**：选完后问自己——他的愤怒真正指向谁？ |


## 第七卷：AI 评价体系


### 二十九、评价定位

AI 评价的角色是 **“规则检测器 + 建议生成器”** ，而非“文学评论家”。

所有评价结果均标注“AI 反馈仅供参考”，保留用户自主判断权。


### 三十、AI 评价分层设计

| 等级 | AI 能做什么 | AI 绝对不能做什么 |
| :--- | :--- | :--- |
| **Lv.0-1** | ①填空是否填了 ②是否有基础语病 | 不做任何文学判断 |
| **Lv.2-3** | ①填空是否填了 ②显性规则检测 ③基础通顺度 | 不做“是否有冲击力/合理性”判断 |
| **Lv.4+** | ①上述所有 ②结构 Checklist ③五感覆盖检测 ④风格倾向描述 | 不做“潜台词是否精妙”“主题是否有深度” |


### 三十一、AI 评价话术规范（强制）

所有 Lv.4+ 的 AI 评价反馈，必须遵循以下话术结构：

| 检测结果 | ❌ 禁止的话术 | ✅ 推荐话术 |
| :--- | :--- | :--- |
| 五感覆盖不足 | “你的场景描写缺少听觉和触觉。” | “你的场景中视觉占了 80%。如果加入一点声音——比如远处警笛的呼啸——氛围会不会更立体？” |
| 对话辨识度弱 | “你的角色说话方式太相似。” | “试着遮住角色名字再读这段对话——你能分辨出谁在说话吗？如果不太清晰，可以尝试给 A 角色更短的句子。” |
| 结构缺失 | “你的故事圈缺少‘顶点’环节。” | “你的故事在‘上升’阶段之后直接跳到了‘回归’。这个跳跃会不会太快了？如果加入一个‘顶点’——让主角得到一切后突然失去——张力会更足。” |
| 直接情绪词过多 | “这里用了太多直接情绪词。” | “这一段中‘愤怒’这个词出现了 3 次。如果删掉这 3 个词，用动作来表达愤怒——比如攥紧的拳头、突然安静下来的声音——效果会不会更含蓄？” |


### 三十二、风格意图标记

| 功能 | 说明 |
| :--- | :--- |
| **用户标记** | 用户可在提交作品时标记“这段我刻意追求极简风格”“这段对话我故意写得平淡” |
| **AI 响应** | 系统收到标记后，自动跳过对应维度的检测（如“风格极简→跳过五感丰富度检测”） |
| **标记后果** | 系统仍会在报告中显示“本次跳过了 XX 项检测（基于你的风格标记）”，用户明确知晓自己选择了“不被检视” |


### 三十三、对话辨识度与潜台词检测

#### 对话辨识度：AI 角色扮演朗读

| 原方案（已废弃） | 修正方案 |
| :--- | :--- |
| AI 直接判断“能否区分角色” | AI 分别扮演 A/B 角色，用不同语气“演”出对话，用户自行判断是否违和 |

#### 潜台词训练：情境限制训练（禁词法）

参见第二十节“情绪传递力”中的禁词法适用范围限定。

### 三十四、用户反馈机制

| 层级 | 交互方式 | 用途 |
| :--- | :--- | :--- |

```
                    ↓

```


## 第九卷：游戏化与留存


### 三十六、渐进式进度可视化

**Lv.0-1 用户看到：**
```
【你的第一个微故事】
①捡种子 ✅ 已完成
②砸石头 🔄 进行中
⑤盖房子 ⏳
完成三步 → 获得《微故事完成证书》
```

**Lv.2-3 用户看到：**
```
【你的第一个短篇故事】
①②⑤ 已完成
③加猛料 🔄 进行中
④画图纸 ⏳
新解锁：矛盾放大三种方法、故事圈模板
```

**Lv.4+ 用户看到：**
```
【你的第一个完整作品】
①-⑤ 已完成
⑥晾一晾 🔄 进行中（预计 24 小时后完成）
⑦搞装修 ⏳
新解锁：结构模型库、读者反馈云、五层修改法
```


### 三十七、段位晋升制

| 段位 | 晋升条件 | 解锁内容 | 平均耗时 |
| :--- | :--- | :--- | :--- |
| 灵感捕手 | 完成 3 张灵感卡片 | 人物素描训练 | 1 天 |
| 故事新手 | 完成 1 个三步闭环 | 微故事证书、矛盾放大 | 3-5 天 |
| 故事工匠 | 完成 3 个三步闭环 | 故事圈结构、四步标准版 | 2-3 周 |
| 结构师 | 完成 2 个四步短篇 | 专属结构模型、七步完整版 | 1-2 个月 |
| 修改高手 | 完成 1 次七步完整闭环 + 五层修改 | 签约模板生成器 | 2-4 个月 |
| 风格探索者 | 完成 2 个七步完整作品 + 完成 3+1 破格比例 | 风格分析工具、读者反馈云 | 4-6 个月 |
| 独立作者 | 完成 3 个七步完整作品 + 完成 3+1 破格比例 | 独立作者认证、作品集导出 | 6-12 个月 |

`[新增]` **“质变节点”中间奖励机制**：

在“故事工匠 → 结构师”之间（从微故事跨越到完整短篇），用户流失风险最高。为此增设以下中间里程碑：

| 里程碑 | 触发条件 | 奖励 |
| :--- | :--- | :--- |
| **短篇骨架完成** | 完成第 1 个四步短篇的“画图纸”（结构大纲） | 解锁“结构师预备役”徽章 + 系统推送“你已经走完了最难的第一步——把一个故事从无到有搭出了骨架” |
| **短篇初稿诞生** | 完成第 1 个四步短篇的“盖房子”（5000 字初稿） | 触发专属庆祝动画 + 发放“初稿勇士”成就 + 赠送 1 次免费“卡文急救包”试用（即使非订阅用户） |
| **第一个完整闭环** | 完成第 1 次 Lv.2-3 完整四步流程 | 系统自动生成“你的第一个短篇”专属信息图（含字数、用时、完成日期、结构完整度） |

上述里程碑均在进度条中以 ⭐ 标记，用户可清晰看到“下一颗星在哪儿”。


### 三十八、五层留存体系

| 层级 | 核心逻辑 | 核心机制 |
| :--- | :--- | :--- |
| 进度（推力） | “我在前进” | 三步→四步→七步渐进解锁、完成证书、中间里程碑 |
| 能力（拉力） | “我在变强” | 技能树点亮、前后作品对比 |
| 场域（引力） | “我不是一个人” | 共修训练营（按阶段分组）、匿名互评 |
| 资产（粘性） | 舍不得放弃 | 灵感库、人物库、作品集、成长档案 |
| 贡献（闭环） | 从“被训练者”到“训练者” | 匿名读者团、读者积分、出题权限 |

## 第十三卷：总结


### 四十四、核心竞争力

| # | 竞争壁垒 | 说明 |
| :--- | :--- | :--- |
| 1 | **渐进式七步法（三层漏斗）** | Lv.0-1 三步 → Lv.2-3 四步 → Lv.4+ 七步，避免认知过载 |
| 2 | **场景五步法破冰** | 解决“面对空白文档写不出”的痛点 |

| 5 | **破格训练模块（3+1）** | 防止套路化同质化，培养真正独立作者 |
| 6 | **AI 角色扮演朗读 + 禁词法（限定范围 + 豁免开关）** | 规避 LLM 潜台词检测技术陷阱，同时尊重风格自由 |
| 7 | **卡文急救包** | 网文作者高频刚需，只提供推演分支 |
| 8 | **签约模板生成器（增值）** | 直接挂钩“过签”刚需，转化路径清晰 |
| 9 | **五力+题库闭环** | 每个专项与训练题目整合，形成“能力→题目→评价”完整链路 |
| 10 | **观察提示卡 + 初级锦囊（选项+追问）** | 启发观察的同时提供脚手架，防止机械照抄 |
| 11 | **严格分层 AI 评价 + 软性话术** | Lv.0-3 仅做填空检测；Lv.4+ 强制开放式话术 |
| 12 | **风格意图标记** | 用户可主动标记“刻意风格”，AI 跳过对应检测 |
| 13 | **中间里程碑机制** | 在流失高发节点（微故事→短篇）插入 3 个奖励点 |
| 14 | **冷却期 AI 兜底** | 冷启动阶段保障互评体验，避免空等流失 |

### 四十六、一句话总结

本产品以**渐进式七步法**为训练流（Lv.0-1 三步闭环 → Lv.2-3 四步标准 → Lv.4+ 七步完整），以**通用模型 + 类型文学专属模型**为结构工具箱，以**场景五步法**为破冰工具，以**冷却期 + 互评反馈云 + 五层修改法**为打磨工艺，以**破格训练（3+1）**为防止套路化的安全阀，以**五力专项 + 题库闭环**为技能支撑——通过“写得出来 → 有张力有结构 → 可诊断可修改 → 敢于打破规则”的递进路径，帮助每个愿意练习的人，**从面对空白文档写不出，到能独立完成一个完整、有张力、不套路的合格故事**，无论他写的是现实题材、幻想世界，还是网文爽文。

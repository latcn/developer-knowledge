## 一、RAG 核心组件

1. **知识嵌入（Knowledge Embedding）**  
   包含： 数据导入 文本分块  信息嵌入 向量存储与索引；
   读取外部知识库内容，分块后通过嵌入模型转化为向量表示，支持多种索引算法。
2. **检索器（Retriever）**  
   包含：检索前处理  基于索引的检索  检索后处理
   从外部知识库中查找与用户输入相关的信息。常用方法：稀疏向量 BM25（或 SPLADE）、密集向量近似最近邻（ANN）检索。
3. **生成器（Generator）**  
   利用检索器返回的相关信息，通过大语言模型生成上下文相关的答案。
---
## 二、RAG 执行流程（2.1–2.10）

### 2.1 数据导入（Loading）
**为什么**：RAG 的知识源来自外部数据，必须先导入。  
**原理**：使用文档加载器（如 LangChain 的 `DirectoryLoader`、`UnstructuredLoader`）读取 PDF、Word、HTML、数据库等。  
**效果**：统一接口，支持异构数据源。  
**实例**：`load` 所有 PDF 文件。  
**替代方案**：手动读取并解析；专用 ETL 工具（如 Airbyte）。

### 2.2 文本分块（Chunking）
**第一性原理**：LLM 输入长度有限，且整篇文档作为检索单元会引入噪声。分块平衡“信息完整性”与“检索颗粒度”。

#### 各分块方法详解

| 方法 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| **递归分块** | 按段落→句子边界递归切分 | 简单通用，保留语义边界 | 无法利用文档结构 | 纯文本默认首选 |
| **Unstructured 结构分块** | 解析标题、表格等元素，按层级切分 | 保留文档结构，提升检索 | 依赖解析库，略慢 | 技术手册、财报 |
| **语义分块** (LlamaIndex) | 计算句子间语义相似度，转折点切分 | 块内语义凝聚 | 计算开销大 | 对精度要求高的场景 |
| **句子窗口** (SentenceWindowNodeParser) | 单句嵌入检索，返回前后窗口 | 兼顾精度与上下文 | 窗口大小固定 | 问答类任务 |
| **父文档检索** (ParentDocumentRetriever) | 小块检索，返回大块父文档 | 精准定位 + 完整上下文 | 存储略高 | 法律条款、论文 |
| **元数据过滤** | 附加时间、来源等标签，检索时过滤 | 大幅提升相关性 | 需手工构造元数据 | 企业知识库 |
| **HyDE** | LLM 生成假设答案，以其嵌入检索 | 消除查询-文档语义鸿沟 | 多一次 LLM 调用 | 低资源领域 |
| **摘要→文档** | 先检索摘要，再扩展至完整文档 | 粗筛+精读，效率高 | 需维护两层索引 | 超长文档 |

#### HyDE 最新进展（2025 年）
通过 **Rocchio 反馈算法** 对 HyDE 生成的假设文档进行扩展项提取与加权，可进一步提升检索准确率（从“一次生成”迈向“生成+反馈迭代”）。

### 2.3 信息嵌入（Embedding）
**第一性原理**：将文本转换为向量，使语义相近的内容在向量空间中距离更近。

#### 向量类型对比
| 类型 | 表示 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| 稀疏嵌入 | 高维词袋 | 可解释，精确匹配 | 维数爆炸 | BM25、关键词 |
| 密集嵌入 | 低维浮点 | 语义泛化强 | 不可解释 | 语义搜索、ANN |
| 二进制向量 | 0/1 位 | 存储极小，速度快 | 精度低 | 图像哈希、快速近似 |

#### 领先嵌入模型（截至 2025‑11）
- **BGE‑M3**：支持密集/稀疏/多向量、100+ 语言、最长 8192 token，开源优秀选择。
- **腾讯 KaLM-Embedding-Gemma3-12B-2511**：MTEB 多语言榜第一（72.32 分）。
- **阿里 Qwen3 Embedding 8B**：曾登顶，得分 70.58。
- **谷歌 Gemini Embedding**：2025 年 7 月发布，得分 68.37。

**选型建议**：多语言高精度 → KaLM / Qwen3；开源 & 多功能 → BGE‑M3；商业 API → Gemini / OpenAI。

### 2.4 向量存储（Vector Store）与索引
**第一性原理**：精确 KNN 需 O(N)，不可扩展。ANN 以可容忍精度损失换取亚线性查询。

#### 索引类型详解
| 索引 | 原理 | 召回率 | 速度 | 内存 | 适用规模 |
|------|------|--------|------|------|----------|
| **FLAT** | 暴力扫描 | 100% | 极慢 | 大 | <1 万 |
| **IVF_FLAT** | 聚类 + 倒排 | 90%+ | 快 | 中 | 百万级 |
| **IVF_PQ** | 乘积量化压缩 | 85‑95% | 快 | 极小 | 十亿级 |
| **HNSW** | 多层图导航 | 95%+ | 极快 | 大 | 百万级（内存充足）|
| **LSH** | 局部敏感哈希 | <80% | 快 | 小 | 近似去重 |

**选型决策树**：
- <1 万 → FLAT
- 内存充足、追求速度 → HNSW
- 内存受限、亿级 → IVF_PQ
- 需要 ACID 事务 → PGVector
- 云原生高并发 → Milvus / Pinecone

**Milvus 操作**：`Search`（向量相似度+排序） vs `Query`（精确过滤，不排序）。

### 2.5 检索前处理（Pre-Retrieval）
对查询进行转换以提升检索精度。

#### 常用技术

| 技术 | 原理 | 效果 | 实例 | 替代 |
|------|------|------|------|------|
| **Text2SQL** | LLM 生成 SQL 查询数据库 | 自然语言访问关系库 | “去年销量最高产品” → SQL | 文本到 API |
| **RePhrase（重写）** | LLM 去除口语冗余 | 提高召回精度 | “嗯…那个…怎么修手机？” → “修手机方法” | 原查询 |
| **Self-query** | LLM 分离语义 + 元数据过滤 | 结构化+语义混合检索 | “去年 AI 文章” → 语义+ `year=2023` | 手动拆解 |
| **MultiQuery** | 生成多个同义查询，合并结果 | 提高覆盖率，减少表达偏差 | 生成“深度学习/神经网络/人工智能应用” | 查询扩展 |
| **查询分解** | 拆解多跳问题为子问题 | 处理复杂推理 | “导演还拍过哪些科幻片” → 先找导演，再找其电影 | Graph RAG |
| **查询澄清** | 交互式询问消歧 | 提升意图理解 | “苹果是指公司还是水果？” | 一次性多义检索 |
| **查询扩展** | 添加同义词、相关词 | 提升召回率 | “气候” + “变暖/危机/温室效应” | 伪相关反馈 |
| **查询路由（逻辑+语义）** | 根据问题选择数据源或模板 | 多数据源调度 | 数学→计算器，常识→维基百科 | 硬编码 if‑else |

### 2.6 基于索引的检索（Retrieval）
利用索引结构从向量存储中查找最相关文档。

#### 高级检索策略

| 策略 | 原理 | 优势 | 局限 |
|------|------|------|------|
| **节点-句子滑动窗口** | 检索块 + 前后固定数量块 | 上下文连续 | 引入无关内容可能 |
| **父子文本块** | 子块检索，返回父块 | 灵活控制粒度 | 需维护层级 |
| **RecursiveRetriever** | 摘要→细节递归检索 | 层级结构效率高 | 实现复杂 |
| **HierarchicalNodeParser** | 树状节点，可向上返回 | 保留文档天然层级 | 树构建成本 |
| **RAPTOR** (2024) | 自底向上聚类 + LLM 摘要构建树 | 整合分散信息 | 效果领域依赖；KV-RAPTOR 优化延迟 |
| **前向/后向扩展** | 按文档顺序附加前后块 | 适合叙事文档 | 依赖顺序关系 |
| **Ensemble Retriever** | BM25 + 密集检索，RRF 融合 | 兼顾精确词匹配与语义 | 需调 k |
| **MultiVectorRetriever** | 为每个文档生成多个向量（摘要/问题） | 提升多角度检索 | 存储膨胀 |

#### RAPTOR 效果与局限（2025 年基准）
- ✅ 在复杂临床问答（CTQA）上，RAPTOR + 小模型甚至优于 GPT‑4o。
- ❌ 在 QuALITY 数据集上无此优势 → 效果存在领域依赖。
- 🆕 **KV-RAPTOR**（2025‑09）通过 KV Cache 压缩进一步降低推理延迟。

### 2.7 检索后处理（Post-Retrieval）
对检索结果清洗、排序、格式化，便于生成器利用。

#### 2.7.1 RRF（Reciprocal Rank Fusion）—— 深度解析

**背景**：多路召回（BM25 + 稠密检索）的分数尺度不同，无法直接加权。  
**核心思想**：仅使用排名，通过倒数函数融合。  
**公式**：
$$
\text{RRFscore}(d) = \sum_{r \in R} \frac{1}{k + \text{rank}_r(d)}
$$
- \(k=60\)（经验值），排名从 1 开始。未出现文档贡献 0。

**示例**（k=60）：

| 文档 | 引擎A排名 | 引擎B排名 | RRF 分数 | 排序 |
|------|-----------|-----------|----------|------|
| Y | 2 | 1 | 1/62+1/61≈0.03252 | 1 |
| X | 1 | 3 | 1/61+1/63≈0.03226 | 2 |
| Z | 3 | 2 | 1/63+1/62≈0.03200 | 3 |
| W | 4 | 4 | 0.03125 | 4 |
| V | 5 | - | 0.01538 | 5 |

**优势**：无需归一化、对离群鲁棒、计算高效、自然处理缺失项。  
**局限性**：忽略检索器置信度、丢弃原始分数、k 值固定可能非最优。

**变体**：加权 RRF（$\sum w_i / (k+r_i)$）、top‑t 截断、与分数混合。  
**失效场景**：噪声检索器、检索器高度同质、某路召回严重不足、k 不当。

**Python 实现**：
```python
def rrf(rankings, k=60):
    scores = {}
    for rank_list in rankings:
        for pos, item in enumerate(rank_list):
            scores[item] = scores.get(item, 0.0) + 1.0 / (k + pos + 1)
    return scores
```

#### 2.7.2 其他重排序方法

| 方法 | 原理 | 精度 | 速度 | 适用 |
|------|------|------|------|------|
| **Cross-Encoder** | 拼接查询+文档，BERT 交互打分 | 最高 | 慢（需 O(N) 次前向） | 精排 top‑K（K≤100） |
| **ColBERT（后期交互）** | 词级双编码 + MaxSim 求和 | 很高 | 中（可预计算文档向量） | 一阶段检索或重排 |
| **ColBERTv2 + PLAID** | 残差压缩 + 候选生成 | 高 | 快（GPU 7 倍加速） | 大规模检索 |
| **WARP（2025）** | 基于 XTR 的检索引擎 | 与 PLAID 相同 | 再提速 3 倍 | 效率优先场景 |
| **Jina Reranker v2** | 多语言编码器，最大 8192 token | 接近 Cross-Encoder | 快 | 多语言长文本 |

#### 2.7.3 压缩（LLMLingua‑2）
**为什么**：提示词过长 → token 浪费 + 延迟增加。  
**原理**：小模型学习去除冗余词，保留关键语义。  
**效果**：压缩 50‑80%，几乎不损失性能。  
**实例**：2000 token → 800 token，LLM 仍能准确回答。

#### 2.7.4 校正（CRAG / Self‑RAG）
| 方法 | 核心机制 | 特点 | 最新扩展 |
|------|----------|------|----------|
| **CRAG** (Corrective RAG) | 评估检索文档相关性，若不相关则触发后备检索（如 Web 搜索） | 即插即用 | CRAG‑MM（多模态问答基准，2025） |
| **Self‑RAG** | 训练 LLM 输出反思标记（`[Retrieval]`、`[Relevant]`、`[Support]`） | 自适应、端到端 | – |

### 2.8 生成器（Generator）
**原理**：将检索到的上下文与用户查询一起输入大语言模型，生成答案。  
**常用模型**：GPT‑4、Claude 3、Llama 3、Qwen 等。  
**优化**：提示词工程（如“仅基于以下上下文回答”）、微调（如 RAFT 方法）。

### 2.9 系统评估（Evaluation）
**为什么需要专门的 RAG 评估**：传统 NLG 指标（BLEU/ROUGE）无法评估检索质量，也无法检测幻觉。

#### 创建评估数据集
- 从真实用户问题中抽样 100‑500 个。
- 专家提供标准答案及来源文档。
- 覆盖：简单事实、多跳推理、否定、模糊查询等。

#### RAG TRIAD 框架
| 指标 | 定义 | 计算方法 | 工具示例 |
|------|------|----------|----------|
| **上下文相关性** | 检索块是否与查询相关 | LLM 判断相关块比例 | RAGAS, TruLens |
| **忠实度** | 答案是否基于上下文（无幻觉） | 分解答案→检查每个陈述是否被上下文支持 | RAGAS `faithfulness` |
| **答案相关性** | 答案是否完整回答查询 | 与标准答案语义相似度或 LLM 打分 | DeepEval `AnswerRelevancy` |

#### 检索评估指标（传统 IR）
- **Precision@K**：top‑K 中相关比例。
- **Recall@K**：检索到的相关文档数 / 库中所有相关文档数。
- **MRR**：首个相关文档的倒数排名均值。
- **MAP**：平均精确率均值。
- ⚠️ **注意**：传统 IR 指标（包括 NDCG、MAP、MRR）基于用户顺序检视文档的假设，而 RAG 中 LLM 可能整体处理检索结果，评估时需结合任务语义综合考量。

#### 评估工具对比（2025‑2026）
| 框架 | 核心优势 | 备注 |
|------|----------|------|
| **RAGAS** | RAG 专注度高、指标全面、LLM-as-a-Judge 开箱即用 | 适合快速评估 |
| **DeepEval** | 灵活性最强、CI/CD 集成友好、G‑Eval 月评估超 1000 万次 | 适合 DevOps 流水线 |
| **TruLens** | 端到端追踪可视化、NDCG@5 排序质量最佳（0.932） | 适合生产监控 |

> **G‑Eval**：最常用的 LLM‑as‑a‑Judge 方法，使用链式推理和概率评分，无需参考答案。

### 2.10 复杂检索策略与范式（Agentic RAG）
**为什么需要**：传统 RAG 一次性检索+生成，无法处理多步推理、工具调用、自我纠错。

#### 四种核心模式

| 模式 | 原理 | 效果 | 实例 | 替代 |
|------|------|------|------|------|
| **反思** | 生成 → 自我评估 → 调整检索策略重试 | 迭代提升质量 | 医疗诊断：检查是否引用最新指南 | 单次 RAG |
| **规划** | 分解任务为子步骤序列执行 | 处理复杂目标 | 金融分析：检索→提取→比较→报告 | 单次生成 |
| **工具使用** | 自动选择并调用外部 API | 扩展能力边界 | 单位转换、计算器、天气查询 | 硬编码工具 |
| **多智能体协作** | 多个专业代理分工协作 | 分工明确，处理超复杂任务 | 客服：FAQ+工单+情感分析+主管 | 单代理循环 |

#### 2025 年多智能体框架生态
- **LangGraph**（LangChain）：生产级 RAG 工作流编排首选，图结构支持循环/分支，生态最成熟。
- **AutoGen**（微软）：对话式多 Agent 协作先驱。
- **CrewAI**：角色化任务编排，适合明确定义的团队协作。
- **其他活跃框架**：LlamaIndex Agents、Semantic Kernel、Pydantic AI、Dify 等约 17 个框架。

## 三、RRF 与其他融合方法的对比

| 方法 | 输入要求 | 是否需归一化 | 典型应用 |
|------|----------|--------------|----------|
| **RRF** | 排名列表 | 否 | 元搜索、多模态检索、推荐系统融合 |
| **Borda 计数** | 排名列表 | 否（需赋分） | 投票系统、集体决策 |
| **最小值/最大值/中位数** | 排名或分数 | 推荐同尺度 | 集成学习简单聚合 |
| **加权求和（分数）** | 原始分数 | 必须归一化 | 相同模型输出融合 |
| **学习排序（LambdaMART）** | 特征+标签 | 通常需要 | 大量标注数据场景 |

**实验结论**：Cormack 等人（SIGIR 2009）证明 RRF 效果显著优于 Borda、Condorcet 及单系统最佳表现，接近或超过有监督方法。

## 四、总结与选型建议表

| 任务 | 推荐工具/方法 | 替代方案 | 关键考量因素 |
|------|--------------|----------|--------------|
| 文本分块 | 递归分块 + 父文档检索 | 语义分块 | 通用性 vs 精度 |
| 嵌入模型 | 腾讯 KaLM / 阿里 Qwen3 (高精度)；BGE‑M3 (开源多功能) | OpenAI text‑embedding‑3 | 开源 vs 商业，多语言需求 |
| 向量索引 | HNSW (内存充足)；IVF_PQ (内存受限) | FLAT (小数据) | 速度 vs 内存 |
| 查询优化 | MultiQuery + Self‑query | 查询扩展 | 意图复杂度 |
| 多路检索融合 | RRF (无监督) | 加权 RRF (有质量先验) | 是否可获取检索器质量权重 |
| 重排序 | Cross‑Encoder (精度优先)；ColBERT (速度优先) | WARP (2025 效率极致) | 延迟预算 |
| 评估 | RAGAS (快速)；DeepEval (CI/CD)；TruLens (可观测) | 人工评估 | 自动化程度与深度 |
| 复杂任务 | Agentic RAG (LangGraph) | 普通 RAG + 多轮 | 任务是否需要多步推理/工具 |

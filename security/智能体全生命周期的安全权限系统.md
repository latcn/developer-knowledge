基于 **Spring AI Alibaba** 和 **AgentScope** 两大框架，结合 OWASP ASI Top 10 的风险模型，设计一套覆盖智能体全生命周期的安全权限系统。

---
## 一、设计目标与核心原则

### 1.1 设计目标

| 目标        | 说明                         |
| :-------- | :------------------------- |
| **身份可信**  | 每个智能体拥有独立、可验证的数字身份，杜绝身份伪造  |
| **权限最小化** | 智能体只获得完成任务所需的最小权限，且权限具有时效性 |
| **执行可隔离** | 所有代码和工具调用在安全沙箱中执行，隔离风险     |
| **过程可观测** | 智能体的每一次推理、工具调用、状态变更均可追溯    |
| **应急可干预** | 提供多层级的人工介入和紧急制动能力          |

### 1.2 核心原则

- **零信任（Never Trust, Always Verify）** ：不信任任何来源，每次操作都重新校验
- **最小代理权限（Least Agency）** ：只授予智能体完成任务所必需的最小自主权和工具权限
- **纵深防御（Defense in Depth）** ：在身份、工具、执行、通信、监控多层部署安全控制
- **默认拒绝（Default Deny）** ：未明确允许的操作一律拒绝

## 三、各层详细设计

### 3.1 第1层：身份与认证层

**目标**：确保每个智能体拥有唯一、可验证的数字身份，防范 ASI03（身份与特权滥用）。

**核心组件**：

#### 3.1.1 智能体身份注册（Agent Identity）

每个智能体在启动时向 **Agent ID Guard** 注册，获取唯一身份标识：

```java
// 基于阿里云 Agent Identity 服务
@Configuration
public class AgentIdentityConfig {
    
    @Bean
    public AgentIdentityManager agentIdentityManager() {
        return AgentIdentityManager.builder()
            .identityProvider(new AgentIdentityProvider() {
                @Override
                public AgentIdentity register(AgentRegistrationRequest request) {
                    // 为每个智能体颁发唯一 DID（去中心化身份）
                    return AgentIdentity.builder()
                        .did("did:agent:" + UUID.randomUUID())
                        .agentName(request.getAgentName())
                        .agentType(request.getAgentType())
                        .issuedAt(Instant.now())
                        .expiresAt(Instant.now().plus(24, ChronoUnit.HOURS))
                        .build();
                }
            })
            .build();
    }
}
```

#### 3.1.2 短期凭证与意图绑定令牌

拒绝使用长期 API Key，改为每次任务颁发短期临时凭证：

```java
@Component
public class CredentialService {
    
    // 为每个任务生成短期令牌
    public TaskCredential issueTaskCredential(String agentDid, String taskId, 
                                               Set<String> allowedTools, 
                                               Duration ttl) {
        String token = JWT.create()
            .withSubject(agentDid)
            .withClaim("taskId", taskId)
            .withClaim("allowedTools", allowedTools)
            .withExpiresAt(Instant.now().plus(ttl))
            .sign(Algorithm.RSA256(privateKey, publicKey));
            
        return TaskCredential.builder()
            .token(token)
            .expiresAt(Instant.now().plus(ttl))
            .scope(allowedTools)
            .build();
    }
}
```

**权限策略基于 Cedar 语言**，支持细粒度的 `permit`/`forbid` 策略：

```
// 策略示例：只允许客服智能体查询订单，不能删除
permit (
    principal is AgentIdentity::OAuthUser,
    action == AIGateway::Action::"order-service.query",
    resource == AIGateway::Gateway::"gw-order"
) when {
    context.input.orderId.startsWith("ORD-") &&
    context.input.userId == context.principal.userId
};
```

### 3.2 第2层：工具权限控制层

**目标**：细粒度控制智能体对工具的访问，防范 ASI02（工具误用）。

**核心组件**：

#### 3.2.1 AgentScope 权限系统（三态决策）

AgentScope 2.0 提供了系统化的权限系统，对每次工具调用给出三种决策：

| 决策 | 说明 |
|:---|:---|
| **ALLOW** | 自动允许执行 |
| **DENY** | 自动拒绝执行 |
| **ASK** | 暂停执行，等待用户确认 |

```java
// AgentScope Java 2.0 权限配置示例
@Configuration
public class PermissionConfig {
    
    @Bean
    public PermissionEngine permissionEngine() {
        return PermissionEngine.builder()
            // 静态规则：基于工具类型
            .rule(ToolType.FILE_READ, PermissionDecision.ALLOW)
            .rule(ToolType.FILE_WRITE, PermissionDecision.ASK)
            .rule(ToolType.SHELL, PermissionDecision.DENY)
            .rule(ToolType.DATABASE_DELETE, PermissionDecision.ASK)
            // 动态规则：基于输入内容
            .dynamicRule((toolCall, context) -> {
                if (toolCall.getToolName().equals("bash") &&
                    toolCall.getArgs().contains("rm -rf")) {
                    return PermissionDecision.DENY;  // 自动拦截危险命令
                }
                return PermissionDecision.ALLOW;
            })
            .build();
    }
}
```

#### 3.2.2 Spring AI Alibaba 人工介入（HITL Hook）

对于高风险操作，通过 `HumanInTheLoopHook` 实现人工审批：

AgentScope 支持 `toolFilter` 机制，**只将白名单内的工具定义发送给大模型**，从源头杜绝模型调用未授权工具的可能：

```java

    })
    .build();
// LLM 只能看到过滤后的工具列表
```

### 3.3 第3层：执行沙箱层

**目标**：隔离执行所有不可信代码和工具，防范 ASI05（意外代码执行）。

**核心组件**：

#### 3.3.1 Spring AI Alibaba GraalVM 安全沙箱

Spring AI Alibaba 的 Assistant Agent 使用 **GraalVM 多语言沙箱** 执行 AI 生成的代码，具备严格的资源隔离能力：

```java
@Component
public class SecureCodeExecutor {
    
    private final GraalVM Sandbox sandbox;
    
    public SecureCodeExecutor() {
        this.sandbox = Sandbox.builder()
            // CPU 限制
            .cpuLimit(Duration.ofSeconds(30))
            // 内存限制
            .memoryLimit(512, MemoryUnit.MB)
            // 禁止文件系统访问
            .fileSystemAccess(FileSystemAccess.NONE)
            // 禁止网络访问
            .networkAccess(NetworkAccess.NONE)
            // 仅允许安全的 Python 标准库
            .allowedModules(Set.of("math", "datetime", "json", "re"))
            .build();
    }
    
    public SandboxResult executeCode(String code, String language) {
        // 代码在 GraalVM 沙箱中隔离执行
        return sandbox.execute(language, code);
    }
}
```

**沙箱安全特性**：
- 资源隔离（CPU/内存限制）
- I/O 隔离（禁止文件系统、网络访问）
- 模块白名单（仅允许安全的标准库）
- 无状态执行（每次执行独立上下文，用完即销毁）

#### 3.3.2 AgentScope Workspace 沙箱

AgentScope 2.0 提供 Workspace 沙箱环境，所有文件读写和命令执行都在隔离容器中运行：

```java
// AgentScope Workspace 沙箱配置
@Configuration
public class WorkspaceConfig {
    
    @Bean
    public Workspace workspace() {
        return Workspace.builder()
            .backend(WorkspaceBackend.DOCKER)  // 基于 Docker 容器隔离

                .forbiddenCommands(Set.of("rm -rf", "sudo", "chmod 777"))
                .networkEgress(NetworkEgress.NONE)  // 禁止外网访问
                .build())
            .persistence(PersistenceStrategy.SESSION)  // 按会话隔离
            .build();
    }
}
```

### 3.4 第4层：通信安全层

**目标**：确保智能体间通信的机密性、完整性和真实性，防范 ASI07（不安全通信）。

**核心组件**：

#### 3.4.1 TLS/mTLS 双向认证

所有智能体间通信使用 mTLS，确保双方身份真实：

#### 3.4.2 消息签名与防重放

每条智能体间消息附带数字签名和防重放标记：

```java
@Component
public class SecureMessageService {
    
    public SignedMessage signMessage(AgentMessage message, PrivateKey privateKey) {
        String payload = message.toJson();
        String signature = RSA.sign(payload, privateKey);
        String nonce = UUID.randomUUID().toString();
        long timestamp = Instant.now().toEpochMilli();
        
        return SignedMessage.builder()
            .payload(payload)
            .signature(signature)
            .nonce(nonce)
            .timestamp(timestamp)
            .senderDid(message.getSenderDid())
            .build();
    }
    
    public boolean verifyMessage(SignedMessage signedMessage, PublicKey publicKey) {
        // 1. 验证签名
        if (!RSA.verify(signedMessage.getPayload(), signedMessage.getSignature(), publicKey)) {
            return false;
        }
        // 2. 防重放：检查 nonce 是否已使用
        if (nonceCache.isUsed(signedMessage.getNonce())) {
            return false;
        }
        // 3. 检查时间戳是否在有效窗口内（5分钟）
        if (Math.abs(Instant.now().toEpochMilli() - signedMessage.getTimestamp()) > 300000) {
            return false;
        }
        return true;
    }
}
```

Spring AI Alibaba 的 Interceptors 在模型调用和工具执行前后介入，提供监控、日志、权限控制等能力：

### 3.6 第6层：应急响应层

**目标**：提供紧急制动和故障隔离能力，防范 ASI08（级联故障）。

**核心组件**：

#### 3.6.1 断路器（Circuit Breaker）

自动检测异常并熔断：

```java
@Component
public class AgentCircuitBreaker {
    
    private final Map<String, CircuitBreakerState> states = new ConcurrentHashMap<>();
    
    public boolean isAllowed(String agentDid) {
        CircuitBreakerState state = states.computeIfAbsent(agentDid, 
            k -> new CircuitBreakerState(5, 30)); // 5次失败后打开，30秒后尝试恢复
        
        if (state.isOpen()) {
            if (state.shouldAttemptReset()) {
                state.halfOpen();
                return true;
            }
            return false;  // 熔断中，拒绝所有请求
        }
        return true;
    }
    
    public void recordFailure(String agentDid) {
        CircuitBreakerState state = states.get(agentDid);
        if (state != null) {
            state.recordFailure();
            if (state.getFailureCount() >= state.getFailureThreshold()) {
                state.open();
                securityAlertService.alert("断路器触发", 
                    Map.of("agentDid", agentDid, "reason", "失败次数超限"));
            }
        }
    }
}
```

#### 3.6.2 Kill Switch（紧急制动）

在基础设施层强制终止智能体：

```java
@Component
public class AgentKillSwitch {
    
    // 全局紧急制动开关
    private final AtomicBoolean globalKillSwitch = new AtomicBoolean(false);
    private final Map<String, AtomicBoolean> agentKillSwitch = new ConcurrentHashMap<>();
    
    @Autowired
    private AgentContextManager contextManager;
    
    @Autowired
    private CredentialRevocationService credentialRevocationService;
    
    // 全局紧急制动
    public void activateGlobalKillSwitch(String reason) {
        globalKillSwitch.set(true);
        securityAlertService.emergency("全局紧急制动已激活", reason);
        // 吊销所有智能体凭证
        credentialRevocationService.revokeAll();
        // 清理所有执行上下文
        contextManager.clearAll();
    }
    
    // 单智能体紧急制动
    public void killAgent(String agentDid, String reason) {
        AtomicBoolean switch_ = agentKillSwitch.computeIfAbsent(agentDid, 
            k -> new AtomicBoolean(false));
        switch_.set(true);
        
        // 1. 吊销该智能体的凭证
        credentialRevocationService.revoke(agentDid);
        // 2. 终止运行中的任务
        contextManager.terminate(agentDid);
        // 3. 记录审计
        auditLogService.logKillSwitch(agentDid, reason);
        // 4. 触发告警
        securityAlertService.alert("智能体被紧急终止", 
            Map.of("agentDid", agentDid, "reason", reason));
    }
    
    // 执行前检查
    public boolean checkBeforeExecution(String agentDid) {
        if (globalKillSwitch.get()) {
            throw new KillSwitchException("全局紧急制动已激活");
        }
        AtomicBoolean switch_ = agentKillSwitch.get(agentDid);
        if (switch_ != null && switch_.get()) {
            throw new KillSwitchException("智能体 " + agentDid + " 已被紧急终止");
        }
        return true;
    }
}
```

#### 3.6.3 补偿回滚（Saga Compensation）

紧急制动触发后，自动回滚已执行的操作：

```java
@Component
public class SagaCompensationService {
    
    private final Map<String, Stack<CompensableAction>> sagaLogs = new ConcurrentHashMap<>();
    
    // 记录可补偿的操作
    public void registerAction(String sessionId, CompensableAction action) {
        sagaLogs.computeIfAbsent(sessionId, k -> new Stack<>()).push(action);
    }
    
    // 紧急回滚
    public void compensate(String sessionId, String reason) {
        Stack<CompensableAction> actions = sagaLogs.get(sessionId);
        if (actions == null) return;
        
        while (!actions.isEmpty()) {
            CompensableAction action = actions.pop();
            try {
                action.compensate();  // 执行补偿操作（撤销）
                auditLogService.logCompensation(sessionId, action, "SUCCESS");
            } catch (Exception e) {
                auditLogService.logCompensation(sessionId, action, "FAILED", e);
                // 人工介入处理
                securityAlertService.alert("补偿回滚失败", 
                    Map.of("sessionId", sessionId, "action", action, "error", e.getMessage()));
            }
        }
        sagaLogs.remove(sessionId);
    }
}
```

## 四、各层与 ASI 风险的对应关系

| ASI 风险 | 对应防御层 | 核心机制 |
|:---|:---|:---|
| **ASI01 目标劫持** | 第1层 身份认证 + 第5层 监控审计 | 意图绑定令牌、输入检测、行为偏离告警 |
| **ASI02 工具误用** | 第2层 权限控制 | AgentScope 三态决策、HITL 审批、工具过滤 |
| **ASI03 身份滥用** | 第1层 身份认证 | Agent Identity、短期凭证、Cedar 策略 |
| **ASI04 供应链漏洞** | 第2层 权限控制 + 第3层 沙箱 | 工具白名单、MCP 认证、沙箱隔离 |
| **ASI05 代码执行** | 第3层 执行沙箱 | GraalVM 沙箱、Workspace 隔离 |
| **ASI06 记忆投毒** | 第5层 监控审计 + 第2层 权限控制 | 记忆写入前校验、数据溯源、写入权限控制 |
| **ASI07 通信不安全** | 第4层 通信安全 | mTLS、消息签名、防重放 |
| **ASI08 级联故障** | 第6层 应急响应 | 断路器、Kill Switch、补偿回滚 |
| **ASI09 人机信任** | 第2层 权限控制 + 第5层 监控 | HITL 强制确认、UI 风险提示、行为偏离检测 |
| **ASI10 流氓智能体** | 第5层 监控审计 + 第6层 应急响应 | 行为基线检测、异常告警、Kill Switch |

## 五、实施路线图

### 第一阶段：基础安全（1-2周）

1. **集成 Agent ID Guard**：为每个智能体建立唯一身份
2. **配置基础工具权限**：使用 AgentScope Permission System 设置 ALLOW/DENY/ASK 规则
3. **启用 Spring AI Alibaba HITL Hook**：为高风险工具配置人工审批

### 第二阶段：执行安全（2-3周）

4. **启用 GraalVM 沙箱**：所有 AI 生成代码在沙箱中执行
5. **配置 AgentScope Workspace**：工具执行隔离到 Docker 容器
6. **部署工具过滤（toolFilter）** ：只将白名单工具定义发送给 LLM

### 第三阶段：监控与应急（2-3周）

7. **接入 AgentScope 事件系统**：全链路可观测
8. **配置 Spring AI Alibaba Interceptors**：模型调用监控与审计
9. **部署 Kill Switch 和断路器**：应急响应能力

### 第四阶段：持续优化（持续进行）

10. **建立行为基线**：持续监控智能体行为偏离
11. **定期红队测试**：模拟 ASI 十大风险攻击
12. **策略迭代**：基于审计日志优化权限策略

## 六、总结

本方案基于 **Spring AI Alibaba** 和 **AgentScope** 两大框架的原生安全能力，构建了六层纵深防御体系：

| 层级 | 框架能力 | 安全目标 |
|:---|:---|:---|
| **身份认证层** | Agent ID Guard + Cedar 策略 | 防范身份伪造与权限滥用 |
| **权限控制层** | AgentScope Permission + Spring AI HITL | 细粒度工具访问控制 |
| **执行沙箱层** | GraalVM + Workspace | 隔离不可信代码执行 |
| **通信安全层** | mTLS + 消息签名 | 防范通信拦截与篡改 |
| **监控审计层** | Event System + Interceptors | 全链路可观测与异常检测 |
| **应急响应层** | Kill Switch + 断路器 | 快速止损与故障隔离 |

通过这套体系，企业可以在 **Spring AI Alibaba**（负责模型调用、工具暴露、Spring 生态整合、代码执行沙箱）和 **AgentScope**（负责智能体编排、权限控制、事件系统、工作区隔离）的协同下，构建安全、可控、可审计的 AI 智能体应用。

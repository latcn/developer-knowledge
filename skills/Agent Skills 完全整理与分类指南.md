## 一、基础设施与通用工具

这类 Skill 是进入整个 Agent Skills 生态的“敲门砖”，或是跨场景、跨项目的基础能力。

### 1. find-skills（技能发现器）
- **功能**：作为整个 Skills 生态的 CLI 入口，提供搜索、安装、更新、卸载等管理功能。通过 `npx skills add` 等命令操作，支持自动检测已安装的 AI 代理（Claude Code、Cursor、Codex 等）并同步配置。
- **应用场景**：任何需要安装或管理其他 Skill 的时候，必须首先安装此 Skill。
- **最佳实践**：**第一个安装**。使用 `npx skills find <关键词>` 快速搜索社区技能，或直接让 AI 助手代劳检索并安装。

### 2. skill-creator / skills-creator（技能创造者）
- **功能**：一个“元技能”，通过自然语言对话引导你创建符合规范的自定义 `SKILL.md` 文件。自动生成 YAML frontmatter、标准指令结构及可选脚本模板。
- **应用场景**：需要将团队工作流、编码规范、重复性任务封装成可复用的 Skill 时。
- **最佳实践**：先明确要解决的问题域，再与 skill-creator 逐步交互生成初版，之后手动微调。生成后放入项目 `.claude/skills/` 目录并提交 Git，实现团队共享。

### 3. planning-with-files（基于文件的项目规划）
- **功能**：接收几十页的 PDF/Word 文档或零散需求，自动生成包含甘特图、里程碑和任务拆解的系统性项目排期表。
- **应用场景**：新项目启动、技术方案设计、复杂任务从 0 到 1 的规划阶段。
- **最佳实践**：提供尽可能多的上下文资料（历史文档、需求列表），让 AI 先产出粗粒度计划，再逐步细化。

### 4. banana-skill-finder（技能导航仪）
- **功能**：聚合类搜索引擎，输入当前场景（如“我要做前端性能优化”），一键匹配 skills.sh、GitHub 等平台上的最优技能组合。
- **应用场景**：不确定该装哪些 Skill 时，用它做“智能推荐”。
- **最佳实践**：与 find-skills 配合使用——先用 banana-skill-finder 发现候选，再用 find-skills 安装。

### 5. Awesome Claude Skills（技能宝库）
- **功能**：并非单个 Skill，而是一个 GitHub 仓库（ComposioHQ/awesome-claude-skills），聚合了 500+ 个社区 Skill 的索引。
- **应用场景**：作为“技能百科全书”，用于浏览和发现冷门但实用的能力。
- **最佳实践**：定期浏览其 README 更新，关注 trending 技能。

## 二、前端开发

聚焦 React/Next.js 生态、UI 设计、性能优化和代码规范。

### 1. frontend-design（Anthropic 官方）—— 前端设计美学
- **功能**：指导 AI 生成有明确美学方向、富有个性的 Web 界面，杜绝“AI 模板感”。支持极简、复古未来、粗野主义、奢华精致等多种风格，并在编码前与用户确认方向。
- **应用场景**：所有需要 AI 生成前端页面的场景（落地页、管理后台、原型）。
- **最佳实践**：与 **web-design-guidelines** 配合使用——前者生成设计，后者审查设计规范。建议在 prompt 中明确指定风格关键词（如 “brutalist minimalism”）。

### 2. frontend-skill（OpenAI 官方）—— 前端代码生成
- **功能**：将设计规范和组件风格编码进指令，让 Codex 生成更符合现代前端最佳实践的代码。可与 figma-implement-design 衔接。
- **应用场景**：使用 Codex 或 OpenAI 相关 Agent 进行前端开发时。
- **最佳实践**：与 **figma-implement-design** 联合使用，覆盖从设计稿到可交付代码的完整链路。

### 3. vercel-react-best-practices（React 性能优化圣经）
- **功能**：包含 70 条性能优化规则（按优先级分为 8 类），覆盖请求瀑布流、包体积、服务端缓存、重渲染等。每条规则配有错误/正确示例，AI 在编码或审查时自动引用。
- **应用场景**：编写或重构 React/Next.js 代码，特别是首屏性能敏感的项目。
- **最佳实践**：将此 Skill 设为项目级（`.claude/skills/`），让 AI 在每次代码生成时自动遵循。定期运行“审查性能”触发检查。

### 4. web-design-guidelines（UI 设计规范审查）
- **功能**：基于 Vercel 公开的 Web 界面设计规范，对指定 UI 代码进行可访问性、间距、排版、交互等多维度审查，输出“文件:行号 + 问题”的清晰报告。
- **应用场景**：前端代码提交前的设计规范自查，或团队 Code Review 环节。
- **最佳实践**：与 frontend-design 搭配使用，形成“生成 → 审查”闭环。建议在 PR 前执行一次全量审查。

### 5. building-native-ui（原生 UI 构建指南）
- **功能**：提供构建 Native 风格 UI 的最佳实践，涵盖移动端适配、平台特定组件等。
- **应用场景**：React Native 或跨平台应用开发。
- **最佳实践**：配合 vercel-react-best-practices 一同使用，兼顾性能和原生体验。

### 6. ui-ux-pro-max（UI/UX 全能顾问）
- **功能**：内置 67 种设计风格、161 套配色方案、57 种字体组合，可自动生成完整的设计系统，并给出交互优化建议。
- **应用场景**：缺乏专业设计师的独立开发或快速原型阶段。
- **最佳实践**：在项目初期使用此 Skill 确定设计基调，产出设计令牌（Design Tokens），后续开发中持续引用。

### 7. figma-implement-design（设计稿转代码）
- **功能**：读取 Figma 设计稿（需整理好图层命名和组件结构），生成接近生产水准的前端代码（React/HTML+CSS）。
- **应用场景**：与设计师协作紧密的团队，希望减少手动还原工作。
- **最佳实践**：提前在 Figma 中规范图层命名（如使用 BEM 或原子设计），生成的代码质量会大幅提升。与 frontend-skill 配合以提升视觉质量。

## 三、后端开发

涵盖 API 设计、鉴权、代码规范与云原生部署。

### 1. better-auth-best-practices（鉴权最佳实践）
- **功能**：提供企业级认证/授权系统的架构指南，涵盖登录、注册、权限校验、Token 刷新、安全漏洞防范等。
- **应用场景**：构建用户系统或需要权限管理的后端服务。
- **最佳实践**：在设计阶段启用此 Skill，让 AI 自动生成符合 OWASP 标准的代码骨架。

### 2. backend-code-review / code-reviewer（后端/通用代码审查）
- **功能**：深度审查后端代码（Java/Go/Python 等），检查性能瓶颈、SQL 优化、异常处理、安全漏洞，输出具体修改建议。
- **应用场景**：团队 PR Review 环节，或定期对存量代码进行质量巡检。
- **最佳实践**：将审查标准（如公司编码规范）补充进项目描述，让 AI 结合上下文给出更精准的建议。

### 3. microsoft-foundry（Azure AI Foundry 全生命周期）
- **功能**：覆盖 Azure AI Foundry 智能体的构建（Docker→ACR）、部署、批量评估、故障排查等全流程，内含多个子技能文档。
- **应用场景**：使用 Azure AI 平台的企业级 AI Agent 开发。
- **最佳实践**：将整个 `microsoft/azure-skills` 仓库安装到项目中，针对不同阶段调用对应子技能（如 `microsoft-foundry-deploy`）。

### 4. azure-ai / azure-deploy / azure-prepare（Azure 全家桶）
- **功能**：
  - **azure-ai**：Azure OpenAI、认知搜索、RAG 应用的 API 使用指南。
  - **azure-deploy**：封装 Azure 云部署最佳实践（CLI 命令、资源组织）。
  - **azure-prepare**：部署前的环境检查（依赖、配置、权限）。
- **应用场景**：Azure 技术栈的完整开发-部署-运维链路。
- **最佳实践**：三个 Skill 配合使用：prepare → deploy，中间穿插 ai 调用。建议在 CI/CD 流水线中集成 prepare 和 deploy。

## 四、测试与质量保证

覆盖单元测试、E2E 自动化、测试修复和组合测试策略。

### 1. tdd / test-driven-development（测试驱动开发教练）
- **功能**：强制 AI 遵循“红灯-绿灯-重构”循环，先编写失败测试，再写最小实现，最后重构。强调“垂直切片”——每个测试覆盖完整行为路径，不依赖内部实现。
- **应用场景**：新模块开发、核心业务逻辑编写，团队有 TDD 文化时效果最佳。
- **最佳实践**：与 **improve-codebase-architecture** 配合，在重构前先补充测试用例。对于已有代码，可先让 AI 生成测试再优化。

### 2. webapp-testing（Web 应用自动化测试）
- **功能**：基于 Playwright 自动执行 UI 交互（点击、输入、导航），验证预期结果并生成测试报告。自动识别现有测试框架，保持风格一致。
- **应用场景**：回归测试、UI 验收、持续集成中的冒烟测试。
- **最佳实践**：在 CI 流水线中定期触发，结合 **gh-fix-ci** 自动修复失败的测试用例。

### 3. Playwright Skill（现代 E2E 自动化）
- **功能**：专为 Playwright 设计，自动生成包含智能等待、异常重试的高级脚本，解决复杂元素（悬浮、iframe）定位困难。
- **应用场景**：需要高稳定性的 E2E 自动化测试项目。
- **最佳实践**：与 **Test Fixing** 搭配使用，减少测试维护成本。

### 4. Test Fixing（测试急救箱）
- **功能**：接收报错日志，快速定位失败原因（如元素变更、数据失效），并直接输出修复后的测试代码。
- **应用场景**：CI/CD 中测试大面积飘红时，紧急排查修复。
- **最佳实践**：将完整的错误堆栈和测试代码一并提供给 AI，获得精准修补方案。

### 5. PyPICT Skill（正交组合测试）
- **功能**：基于微软 PICT 算法，生成成对组合（Pairwise）测试用例，以最少用例覆盖最多参数交互场景。
- **应用场景**：多参数组合搜索、筛选条件测试（电商、报表系统）。
- **最佳实践**：先定义好所有参数及取值，交给此 Skill 生成精简用例，再手工补充少数高风险场景。

## 五、架构设计与代码审查

聚焦系统架构、技术债务、方案验证和重构。

### 1. grill-me（灵魂拷问型架构审查）
- **功能**：在动手编码前，像资深面试官一样系统性追问方案细节（备选方案、扩展性、边界条件、降级策略），帮助发现设计漏洞。
- **应用场景**：设计评审、技术选型、重大项目启动前的方案验证。
- **最佳实践**：在团队设计讨论会中调用此 Skill，让 AI 扮演“挑战者”角色，输出问题清单后再集体决策。

### 2. improve-codebase-architecture（架构体检师）
- **功能**：基于《A Philosophy of Software Design》的“深模块”理念，扫描代码库，识别接口过复杂、职责不清、耦合过重的“技术债”，并生成重构 RFC（Issue 格式）。
- **应用场景**：接手老旧项目、准备大规模重构前。
- **最佳实践**：定期（如每季度）运行一次，产出重构计划，按优先级逐步实施。

### 3. create-plan（执行计划生成）
- **功能**：强制 AI 在写代码前拆解任务，输出可审阅的分步执行计划（含文件修改、依赖关系），批准后方可动手。
- **应用场景**：多文件、多模块的中大型功能开发，避免盲目编码。
- **最佳实践**：将此 Skill 设为默认行为，尤其适合新人或临时团队，确保方向一致。

### 4. Superpowers（工程纪律手册）
- **功能**：集成 20+ 个子技能的工作流框架，包括头脑风暴（强制需求澄清）、子代理并行开发、TDD、代码审查（双阶段）、Git Worktree 管理等。强调“流程大于提示词”。
- **应用场景**：中大型项目交付、对质量要求严格的团队。
- **最佳实践**：安装后优先使用 `brainstorming` 子技能，再逐步引入 `subagent-driven-development`。简单任务可跳过以节省时间。

### 5. GSD（Get Shit Done）—— 极简执行
- **功能**：跳过所有规划与审查，直接执行用户指令。适合确定性高的重复性任务。
- **应用场景**：紧急修复、已知流程的批量操作。
- **最佳实践****：仅在 100% 确定要做什么时使用，避免因上下文缺失导致错误操作。

### 6. GStack（YC 风格迭代工作流）
- **功能**：将 Y Combinator 推崇的“快速迭代、持续交付”理念编码为 AI 工作流，强调频繁发布和用户反馈闭环。
- **应用场景**：创业项目、MVP 开发。
- **最佳实践**：与 Superpowers 互补——在产品早期用 GStack 加速迭代，成熟后切换至 Superpowers 保障质量。

## 六、内容创作与视频

面向非代码内容生成，如视频、PPT、文案等。

### 1. remotion-best-practices（React 视频制作）
- **功能**：封装 Remotion 官方 30+ 条最佳实践，涵盖动画、音视频处理、3D 集成、字幕、数据可视化等，指导 AI 用 React 代码生成高质量视频。
- **应用场景**：产品宣传视频、动态数据报告、批量生成个性化视频。
- **最佳实践**：先设计好视频的“组件树”，再让 AI 基于此 Skill 编写代码，可实现参数化批量渲染。

### 2. video-edit（智能视频编辑路由）
- **功能**：根据用户意图智能路由到 3 个 AI 视频编辑模型（Wan / Kling / Lucy），自动选择最合适的模型执行剪辑、特效或生成任务。
- **应用场景**：非技术用户快速制作短视频内容。
- **最佳实践**：明确描述视频效果（如“慢动作+复古色调”），让 AI 选择最佳引擎。

### 3. NanoBanana PPT Skills（PPT 排版助手）
- **功能**：专注 PPT 大纲生成、内容逻辑梳理和排版建议，5 分钟输出高质量商业汇报框架。
- **应用场景**：写汇报、路演、培训材料时快速搭建结构。
- **最佳实践**：提供核心观点和数据集，让 AI 生成多套叙事逻辑，再人工润色。

### 4. copywriting & copy-editing（文案与精修）
- **功能**：提供爆款文案生成、语感润色、多角度创意（小红书、微信长文等），运用情绪价值提升吸引力。
- **应用场景**：市场宣传、社交媒体运营。
- **最佳实践**：明确目标受众和平台调性，AI 会生成 10+ 个不同侧重的版本供选择。

### 5. social-content & marketing-psychology（营销心理学）
- **功能**：运用损失厌恶、锚定效应等心理学原理，包装内容以提升阅读量和互动率。
- **应用场景**：活动策划、用户增长内容。
- **最佳实践**：与 copywriting 配合使用，先用心理学框架确定策略，再生成具体文案。

## 七、AI 工具链与集成

构建 AI 基础设施、连接外部服务、开发 CLI 工具。

### 1. mcp-builder（MCP Server 构建向导）
- **功能**：通过四阶段工作流（规划→实现→评估→优化）引导构建符合最佳实践的 MCP（Model Context Protocol）服务器，并内置评估框架验证结果。
- **应用场景**：为 AI Agent 开发自定义工具能力，或构建内部 AI 平台。
- **最佳实践**：先在本地沙箱验证 MCP Server 的工具调用，再部署到生产。与 cli-creator 配合封装常用操作。

### 2. composio-connect / Composio（连接 1000+ 外部服务）
- **功能**：通过 Composio CLI，让 AI 直接操作 Jira、Linear、Slack、GitHub、Notion 等 1000+ 应用，执行创建任务、发送消息、更新工单等操作。
- **应用场景**：自动化跨平台工作流（如从 GitHub Issue 自动创建 Jira 任务）。
- **最佳实践**：先安装 composio 并配置 OAuth 凭证，再让 AI 执行“在 Slack 中通知 PR 合并”等指令。

### 3. cli-creator（CLI 工具生成器）
- **功能**：将重复性命令、脚本或 API 调用封装为符合 Codex 契约的可复用 CLI 工具，支持 PATH 调用和 JSON 输出，并自动生成配套 Skill。
- **应用场景**：基础设施工程师封装运维脚本，或团队统一内部工具链。
- **最佳实践**：将常用组合命令（如“部署 + 健康检查”）封装为一个 CLI，后续可跨项目复用。

### 4. gh-fix-ci（CI 失败自动诊断）
- **功能**：读取失败的 GitHub Actions 运行记录，自动分析原因（依赖问题、环境变量、测试用例）并给出修复建议。
- **应用场景**：频繁遭遇 CI 红牌的开发团队。
- **最佳实践**：将诊断结果直接应用到修复中，可结合 webapp-testing 重新生成稳定的测试脚本。

- **最佳实践**：结合市场调研数据，让 AI 输出多个定价组合的预测收益，辅助决策。

## 九、安全与合规

代码安全、威胁建模和漏洞扫描。

### 1. security-review（安全漏洞扫描）
- **功能**：自动检测 SQL 注入、XSS、敏感信息泄露、不安全依赖、认证缺陷等常见安全风险，在 PR 前运行。
- **应用场景**：每次提交代码前的安全检查。
- **最佳实践**：集成到 CI 流水线的 PR 步骤，自动阻断高风险变更。

### 2. security-threat-model（AI 辅助威胁建模）
- **功能**：引导 AI 系统分析代码仓库的信任边界、攻击路径和风险点，输出可用于技术评审的威胁分析文档。
- **应用场景**：安全合规要求高的金融、医疗领域项目。
- **最佳实践**：在架构设计阶段进行威胁建模，将产出文档作为设计评审的必须输入。

## 十、其他特色工具

以下技能功能独特，不易归类到上述板块。

### 1. agent-browser（AI 浏览器自动化）
- **功能**：让 AI 直接控制浏览器（Headless/Real Chrome/Cloud Remote），跨会话保持 Cookie 和标签页状态。支持 15+ 命令类别（导航、点击、截图、抓取）。
- **应用场景**：爬虫、自动化测试、需要登录态的操作（如批量创建 Issue）。
- **最佳实践**：敏感操作使用 Real Chrome 模式（本地 Profile），避免在 Cloud Remote 中输入密码。

### 2. grill-with-docs（文档化拷问）
- **功能**：grill-me 的增强版，在拷问方案的同时自动更新项目 CONTEXT.md 和 ADR（架构决策记录），确保知识沉淀。
- **应用场景**：需要长期维护的架构决策过程。
- **最佳实践**：每次设计讨论后运行此 Skill，自动记录决策背景和备选方案。

### 3. soultrace（人格化 AI 助手）
- **功能**：通过实时问答动态描绘用户性格画像，使 AI 输出更契合个人偏好（代码风格、沟通语气等）。
- **应用场景**：长期使用同一 AI 助手的开发者，希望获得个性化体验。
- **最佳实践**：不涉及业务敏感信息，可安装在全局作用域。

### 4. Karpathy Guidelines（顶级工程师思维框架）
- **功能**：将 Andrej Karpathy 的 AI 编码四原则（先读代码再修改、精准修改、优先简洁、核对需求）编码为行为约束，改变 AI 的“盲目自信”。
- **应用场景**：新项目启动、任何需要 AI 先理解再动手的场景。
- **最佳实践**：作为默认行为 Skill 安装，尤其在探索陌生代码库时效果显著。

## 安装通用说明

绝大多数 Skill 均可通过以下方式安装：

```bash
# 首先安装基础 CLI（即 find-skills）
npx skills add vercel-labs/skills --skill find-skills

# 然后安装任意技能（示例）
npx skills add <owner>/<repo> --skill <skill-name>
```

**项目级 vs 个人级**：
- 个人级：`~/.claude/skills/`（所有项目生效）
- 项目级：`.claude/skills/`（推荐，可随代码库共享）

**Cursor 用户注意**：需要软链 `~/.cursor/skills` 到 `~/.cursor/skills-cursor`。

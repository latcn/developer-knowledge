
## 一、Skill 定位与核心承诺

### 1.1 定位

一个**多轮对话驱动、支持批量生成、可中断恢复**的分布式系统设计原则推导工具。适用于 Agent 平台（Coze、Dify）或标准 LLM 对话框（ChatGPT、Claude）。

### 1.2 核心承诺

1. **不产生幻觉**：参数默认值不确定时使用 `[需查阅官方文档确认]`，严禁猜测。
2. **可选交互模式**：支持“逐个确认”或“全部生成”（安全批次），支持模式切换。
3. **可中断恢复**：提供 JSON 快照（Keys 强制英文）和携带完整规划蓝图的人类可读指令（中英文兼容）。
4. **状态机完备**：支持覆盖（修改已生成原则）、回退截断、终态锁定与硬隔离重置。

### 1.3 使用边界

- 不覆盖纯业务逻辑、组织管理。
- 若用户输入过于模糊（仅“设计一个系统”），Skill **必须拒绝直接生成**，进入追问流程。

## 二、理论基础与分类框架

> 以下 30 项问题域的极简名称列表应放入 **System Prompt**。

### 2.1 极简映射表（中文语义，一行）

```text
D1:数据容量,D2:数据容错,D3:数据安全,D4:数据可运维,
C1:计算资源,C2:计算容错,C3:计算安全,C4:计算可运维,
N1:网络带宽,N2:通信容错,N3:通信安全,N4:通信可运维,
T1:时间精度,T2:时间容错,T3:时间安全,T4:时间可运维,
X1:一致性模型,X2:分布式事务,X3:并发控制,X4:冗余复制,
X5:分区扩展,X6:负载均衡,X7:分布式锁,X8:故障检测,
X9:安全防御,X10:可观测性,X11:测试验证,X12:配置演化,
X13:成本优化,X14:硬件加速
```

### 2.2 封闭域与语言约束

- **封闭域**：主归属与关联域（Domain ID）的编号**必须严格且仅限**从上述 30 个 ID（D1~T4, X1~X14）中选取，**严禁自创**。关联域列表**严禁包含**主归属 ID，必须自动去重。
- **语言隔离**：JSON 的 **Key（键名，如 `status`, `plan`）必须且只能使用英文**；但 JSON 的 **Value（值，如 `"X4"`, `"消息队列"`）以及输出给用户的 Markdown 文本，必须使用用户所在的语言（如中文）**。

## 三、交互模式与中断恢复

### 3.1 首次对话模板

```text
收到。我将为你生成分布式系统设计原则。

请选择交互模式：
A. 逐个生成（每输出一个原则后需确认，适合深入探讨，支持中途修改）
B. 全部生成（自动按顺序输出，每次最多2个后暂停，适合快速产出；批次内不支持修改）

请回复 A 或 B，并告诉我：
1. 系统类型（如：消息队列、KV存储、RPC框架）
2. 核心关注（性能/可靠性/扩展性/一致性/安全/可观测，可多选）
3. 部署环境（单数据中心/跨地域/云原生/边缘，可选）

示例：B，系统类型：消息队列，核心关注：性能、可靠性
```

### 3.2 模式 A：逐个生成（交互式，支持修改）

- 筛选问题域列表（3~6个），输出列表（包含对应的 Domain ID 规划），并请求确认。
- 每生成一个原则后，暂停询问“继续下一个？”。
- 用户可回复：
    - `继续` → 生成下一个。
    - `修改[生成序号]` → 重新生成该原则，并**触发回退截断**（见 6.1）。
    - `切换模式B` → 从当前位置切换为批量生成。

### 3.3 模式 B：全部生成（安全批次机制）

- 每次最多连续输出 **2 个完整原则**。
- 输出 2 个原则后，**必须暂停**并输出 `<state_snapshot>`，提示用户回复 `继续` 或 `切换模式A`。
- **批次内不支持修改**。若用户输入“修改[序号]”，应提示：“模式 B 批次内不支持修改。请回复‘切换模式A并修改[序号]’。”

### 3.4 中断恢复（携带完整规划蓝图，中英文兼容）

**Skill 每次输出结束时的提示**（便于用户复制）：

```text
如需在全新对话中恢复进度，请复制以下指令：
恢复进度：系统[消息队列]，关注[性能,可靠性]，
已完成第[1,2]个原则（对应[X4,X5]），
剩余规划：第[3]个原则对应[X7]，第[4]个原则对应[X10]。
请继续生成第[3]个原则。
```

_(注：LLM 需同时识别中文“恢复进度”与英文“Restore progress”语义)_

### 3.5 全局权衡矩阵（终态锁定、Token 保护与硬隔离重置）

- 所有原则输出完毕后，提示用户回复“生成矩阵”。
- 用户确认后，输出全局矩阵，然后输出**最后一次终态快照**（`status=completed`），并提示：
    
    ```text
    所有原则及全局矩阵均已生成完毕。此后进入只读问答模式。
    您可以针对具体原则提问，但此阶段的参数修正将不会被持久化保存。如需修正并保存，请回复“重新开始”。
    请注意：这是最后一次输出状态快照，后续只读问答中将不再输出，以节省 Token。
    ```
    
- **终态锁定与 Token 保护**：
    - 当 `status` 变为 `completed` 且**已经输出过终态快照**后，后续的所有只读问答中，LLM **严禁再次输出 `<state_snapshot>` 标签**。（Agent 平台侧将通过代码节点透传上一轮状态，见 7.2）。
    - 若用户主动询问“请再次显示状态快照”，LLM 可重新输出已保存的终态快照（但不应修改内容）。
- **硬隔离重置（防上下文污染与幽灵快照）**：
    - 若用户输入“重新开始”，LLM 必须在输出任何新内容前，首先输出 `<context_reset/>` 标签。
    - **互斥铁律**：输出 `<context_reset/>` 时，**严禁**在同一次回复中输出 `<state_snapshot>`。
    - 输出该标签后，LLM 必须在内部逻辑中彻底清空并无视之前的所有规划蓝图（Plan）、约束和修正，将其视为全新会话，重新回到 Phase 0 追问。

## 四、核心工作流（5+1阶段）

- **Phase 0**：场景解析。若输入模糊则拒绝并追问。筛选 3~6 个问题域（含 P0/P1/P2 优先级），输出规划蓝图。
- **Phase 1**：单一原则推导。技术类用 5.1，人/流程类用 5.2。
- **Phase 2**：真实性硬约束。不确定参数用 `[需查阅官方文档确认]`，禁编造源码行号。
- **Phase 3**：归属与交叉引用。严格遵循封闭域与去重约束。
- **Phase 4**：反模式检查。动态联想并输出规避措施。
- **Phase 5**：人/流程类验证。提供混沌注入、监控、巡检模板。
- **Phase 6**：全局权衡矩阵。输出冲突与权衡建议，随后进入终态。

## 六、状态快照（覆盖语义 + 回退截断）

### 6.1 JSON 格式（强制英文 Key，纯净无标记）

**关键规则**：

- `<state_snapshot>` 标签内**必须且只能**包含合法的 JSON 字符串，**严禁**添加 Markdown 标记（如 ` ```json `）。
- **值转义铁律**：JSON 的任何 Value（值）中，严禁直接包含 `</state_snapshot>` 字符串。若业务文本必须包含，请使用反斜杠转义（如 `<\/state_snapshot>`）或标准小写 Unicode 转义（如 `\u003c/state_snapshot\u003e`）。
- **回退截断**：若修改序号 N 小于 `completed_indices` 最大值，必须移除大于 N 的所有序号，强制重新生成后续原则。

**JSON 示例**（状态为 `in_progress` 时）：

```text
<state_snapshot>
{
  "status": "in_progress",
  "total": 4,
  "completed_indices": [1,2],
  "overridden_indices": [],
  "next_index": 3,
  "plan": {
    "1": "X4",
    "2": "X5",
    "3": "X7",
    "4": "X10"
  },
  "user_constraints": {
    "system_type": "消息队列",
    "focus": ["性能", "可靠性"],
    "mode": "A"
  },
  "user_corrections": {}
}
</state_snapshot>
```

**终态示例**（`status=completed`，仅在最后一次输出，注意：严禁使用 `{...}` 等非法省略语法）：

```text
<state_snapshot>
{
  "status": "completed",
  "total": 4,
  "completed_indices": [1,2,3,4],
  "overridden_indices": [1],
  "next_index": null,
  "plan": {"1":"X4","2":"X5","3":"X7","4":"X10"},
  "user_constraints": {
    "system_type": "消息队列",
    "focus": ["性能", "可靠性"],
    "mode": "A"
  },
  "user_corrections": {}
}
</state_snapshot>
```

## 七、部署指导（含状态透传与精准正则容错）

### 7.1 组件存放与初始化

|组件|存放位置|说明|
|---|---|---|
|System Prompt|平台系统提示词|包含角色、工作流、2.1映射表、2.2约束|
|模板 (5.1/5.2)|外部变量/Few-Shot|动态注入|
|`session_state`|平台会话变量|**初始值必须设为空字符串 `""`**，严禁设为 `null`，防止下游拼接报错。|

### 7.2 JSON 提取与状态透传（纯 Python 标准库，防状态丢失）

在 Dify/Coze 代码节点中使用以下代码。**关键：必须将上一轮的 `session_state` 作为入参传入（变量名 `current_state`），以实现终态后的状态透传。**

```python
import re
import json

def main(llm_output: str, current_state: str) -> dict:
    # 1. 优先提取 state_snapshot（非贪婪匹配，配合 6.1 节值转义铁律）
    match = re.search(r'<state_snapshot>(.*?)</state_snapshot>', llm_output, re.DOTALL)
    
    if match:
        json_str = match.group(1).strip()
        # 去除 LLM 偶尔生成的 Markdown 代码块标记（仅匹配字符串真正的开头和结尾，防止误删 JSON 内部的代码块）
        json_str = re.sub(r'^```json\s*|\s*```$', '', json_str, flags=re.DOTALL).strip()
        # 清洗常见 JSON 错误：去除尾随逗号
        json_str = re.sub(r',\s*([\]}])', r'\1', json_str)
        
        try:
            parsed = json.loads(json_str)
            return {
                "success": True, 
                "data": json.dumps(parsed, ensure_ascii=False), 
                "is_passthrough": False
            }
        except json.JSONDecodeError:
            pass # 解析失败，落入下方透传逻辑

    # 2. 若未提取到合法快照，检查是否为硬隔离重置
    if '<context_reset/>' in llm_output:
        return {
            "success": True,
            "data": "",
            "is_passthrough": False
        }

    # 3. 【关键防丢失机制】：若 LLM 未输出快照且非重置（如终态后的只读问答），
    # 直接透传上一轮的 current_state，防止状态被覆盖清空。
    return {
        "success": True, 
        "data": current_state if current_state else "", 
        "is_passthrough": True
    }
```

## 八、降级策略与边界处理

### 8.1 输入模糊时的追问

若用户输入不包含系统类型或核心关注，输出：

```text
信息不足，无法生成有效原则。请至少提供：
1. 系统类型（如：数据库、消息队列、缓存）
2. 核心关注（如：性能、可靠性）
例如：“设计一个高性能消息队列”
```

### 8.2 Token 超限时的分段输出

- 模式 B 已内置安全批次（每次最多 2 个原则），天然避免截断。

### 8.3 模式切换与回退截断

- 模式 A 可随时回复 `切换模式B` → 从当前原则序号开始进入批量生成。
- 模式 B 批次内不支持修改，但可回复 `切换模式A并修改[序号]` → 中断当前批次，回退到指定序号（触发回退截断），并切换为交互式模式。

## 九、自我进化（真实能力边界）

### 9.1 本次会话内的修正

- 用户提出修正（如“X 参数默认值实际是 100”），仅在 `status` 为 `in_progress` 时，将修正记录到 `user_corrections` 中。
- 终态后不再更新 `user_corrections`（见 3.5）。
- 后续原则生成时优先使用修正值。

### 9.2 持久化（需外接知识库）

- **若无外接 RAG**：不承诺“更新内部知识库”，仅记录到状态快照。
- **若有外接 RAG**：定义工具调用 `update_knowledge_base`。

### 9.3 负反馈收集

每轮对话结束时，输出简短反馈表单：

```text
本次生成是否有以下问题？
- [ ] 参数推荐不准确
- [ ] 原则不适用于我的场景
- [ ] 缺少关键原则
- [ ] 验证方法不可行
请回复编号或具体描述。
```
